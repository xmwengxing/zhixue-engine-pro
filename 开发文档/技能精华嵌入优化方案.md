# 已装教育类 Skill 精华嵌入优化方案

> 版本：v1.0（2026-08-03）｜性质：**方案评审稿，未改动任何代码**
> 分析对象：`edu-class-diagnosis`（班级薄弱点诊断）、`edu-paper-builder`（智能组卷）、`edu-learning-path`（学习路径规划）
> 说明：用户列表中的 `edu-class-diagnosis` 出现两次，实为同一技能；另已安装的 `edu-exam-item-gen`（命题蓝图/难度校准/评分标准）与组卷强相关，方案中顺带提及，可一并评估。

## 一、总体判断

| 技能 | 核心方法论 | 与本项目契合度 | 结论 |
|---|---|---|---|
| edu-class-diagnosis | 薄弱知识点定位 → gap_level 分级 → priority_score 排序 → 教学建议 | ★★★★☆（个体侧契合，班级侧缺数据模型） | **方法论可直接产品化**，班级聚合能力需产品决策 |
| edu-paper-builder | 双向细目表 × 难度分布约束 × 组卷排版 × 答案评分标准 | ★★★★★（项目已有组卷雏形，缺细目表约束） | **直接增强现有组卷链路** |
| edu-learning-path | 分阶段路线图（阶段目标/里程碑/先修依赖/周计划） | ★★★☆☆（PROFILE 已有训练计划雏形） | **增强训练计划 + CUSTOM 新增目标拆解** |

核心结论：**三个技能都不是"整包嵌入"，而是把其中的判定模型、数据结构、提示词方法论沉淀进现有服务**，与本项目已有的题库、学情档案、训练计划、组卷链路天然互补，无需引入运行时依赖。

## 二、技能精华提炼（对照项目现状）

### 2.1 edu-class-diagnosis → 薄弱点诊断方法论

**技能精华**：
- `WeakPoint` 结构化工件：`{ kp, gap_level(1-5), evidence, blocks_followup, urgency(高/中/低), priority_score, confidence }`
- gap_level 由失分率映射：<15%→1、15-35%→2、35-55%→3、55-75%→4、>75%→5
- `priority_score = gap_level × 核心度权重（课标核心×1.3）+ blocks_followup×1`
- 教学建议：补救形式（微课/专题讲练/分层练习）、建议课时、题源类型
- 合规护栏：仅作教学参考、不贴标签、数据本地不泄露

**项目现状（差距）**：
- `subjectLearningStateService.getSubjectSummary` 的 `weakPointsTop5` 只有 `{point, score}`，**无优先级、无阻塞关系、无 urgency、无教学建议**
- `questionSelectionService` 的 AI 选题按错误次数/IRT 排序，未用 priority_score
- 学期归档 `archiveTask` 的薄弱点 TOP5 也是纯频次统计
- 家长端学情总览只展示分数条，无"高/中/低紧迫度"与"建议补法"
- 项目是**家长-学员 1v1 平台**，无"班级"聚合；技能中"班级画像/多班对比"能力当前无处安放

### 2.2 edu-paper-builder → 智能组卷方法论

**技能精华**：
- 双向细目表（blueprint）：知识点 × 题型 × 难度 × 题量配额，确保不重不漏、梯度递进
- 难度分布约束：易:中:难 = 4:4:2 式显式比例
- 组卷排版规范：选择→填空→解答，标注分值与预估时长
- 答案与评分细则（关键步骤分）
- 异常处理：约束不足先追问、难度×题量超时提示、知识点重叠自动合并

**项目现状（差距）**：
- `buildExamPaperTask`（RANDOM 分支）→ `pickRandomQuestions`：只做 `types + difficultyMin/Max + knowledgePoints hasSome + count` 的**洗牌取前 N**，**无难度分布配额、无知识点覆盖率保证**（可能抽到全是同知识点/同难度）
- 无"预估时长"字段；`QuestionPaper` 无 blueprint 结构
- 管理端建卷/导入无难度分布配置
- 水平评估 AI 组卷（`loadAssessmentQuestionIds`）随机取 20 题，同样无细目约束

### 2.3 edu-learning-path → 学习路径方法论

**技能精华**：
- 目标拆解为 3-6 阶段，每阶段含：**可验证的完成标准**、核心知识点、里程碑任务、预估时长
- **先修依赖（prerequisites）** 标注 + 可跳过的进阶项
- 周计划节奏表（可填写、可复盘）
- 异常处理：信息缺失最多 3 追问、目标过大收敛、时间不合理提示最小可行版本

**项目现状（差距）**：
- PROFILE 模式有 `trainingPlanData`（foundation/improvement/application 三阶段），但阶段内**无"完成标准/里程碑自测"**，无先修依赖图
- CUSTOM 模式**完全没有学习路径概念**（只有单元范围勾选）
- 家长发任务时 `goal` 是自由文本，AI 只把它拼进指令，未拆解为分阶段目标
- "已 N 天未训练"只有告警，无"本周建议完成量"的节奏引导

## 三、嵌入方案总览（映射矩阵）

| 编号 | 技能精华 | 嵌入到项目哪里 | 价值 |
|---|---|---|---|
| A1 | WeakPoint 结构化（gap/priority/urgency/confidence） | `subjectLearningStateService`（学情档案）+ `getSubjectSummary` | 薄弱点从"分数列表"升级为"可行动清单" |
| A2 | priority_score 排序 | `questionSelectionService`（AI 选题）+ `archiveTask`（学期归档薄弱点） | 出题/归档优先补最该补的 |
| A3 | 教学建议（补法/课时/题源） | 学情总览前端 + 学期总结 AI prompt | 家长/学员拿到"怎么补"而非只看到"哪里弱" |
| B1 | 双向细目表（blueprint） | 新 `ExamBlueprint` 配置 + `pickRandomQuestions` 按配额抽题 | 组卷不再随机凑数，质量接近手工命题 |
| B2 | 难度分布（易:中:难） | 专项组卷表单 + 管理端建卷表单 | 显式控制梯度 |
| B3 | 预估时长 + 排版规范 | 组卷任务详情/电子答题专区 | 更接近真实考试体验 |
| C1 | 分阶段目标 + 完成标准 | PROFILE `trainingPlanData` 阶段增强 | 训练计划可自测、可回退 |
| C2 | 先修依赖（prerequisites） | 知识点模型 + 出题/选题排序 | 阻塞关系驱动补弱（与 A2 联动） |
| C3 | 目标拆解 | CUSTOM 创建任务时 AI 拆 `goal` → 分阶段目标存 config | CUSTOM 也获得"路径感" |
| C4 | 周计划/训练节奏 | 防中断联动：按"已 N 天未训练"给本周建议量 | 降低中断率 |
| C5 | 合规护栏 | 报告/总结/建议文案统一口径 | 教育数据伦理合规 |

## 四、分模块详细方案

### 模块 A：学情薄弱点结构化（对应技能 1，P0）

**数据层**（`SubjectLearningState` 的 masteryMap 结构扩展，Json 兼容，无需新表）：
```json
// masteryMap[point] 新增字段
{
  "point": "全等三角形判定",
  "score": 32,
  "gap_level": 4,                 // 由失分率映射：<15→1 ... >75→5
  "priority_score": 5.2,          // gap_level × 核心度(1.0/1.3) + blocks_followup
  "blocks_followup": true,        // 是否阻塞后续知识点（先修依赖图判断）
  "urgency": "高",                 // 高/中/低
  "confidence": "高",              // 依据数据充分度
  "evidence": "近3轮错题 12 次，失分率 68%",
  "suggestions": ["专题讲练 2 课时", "基础巩固题 + 综合变式各 5 题"]
}
```

**改动点**：
1. `subjectLearningStateService`：
   - `updateFromSession` 增量更新时**同时维护 gap_level/priority_score**（用错误次数/该知识点出题数算失分率）
   - 新增 `getWeakPointPriorityList()`：按 priority_score 排序输出 WeakPoint[]
2. `getSubjectSummary`：`weakPointsTop5` 升级为带 urgency/priority_score 的结构（**对 agentContextBuilder 透明兼容**——它只消费 point/score，加字段不破坏）
3. `questionSelectionService`：AI 选题/规则选题时按 priority_score 降序优先选阻塞点
4. `archiveTask.collectSemesterStats`：薄弱点 TOP5 直接用 priority 排序结果
5. 前端 `SubjectLearningStateView`：薄弱点卡片显示「高/中/低紧迫度」徽标 + 一行教学建议

### 模块 B：智能组卷升级（对应技能 2，P0）

**数据层**：`ExamPaperConfig` 新增可选 `blueprint`：
```ts
interface ExamBlueprint {
  difficultyDist: { easy: number; medium: number; hard: number }; // 占比，如 {40,40,20}
  knowledgePoints?: string[];      // 目标知识点覆盖（不重不漏）
  typeDist?: Record<string, number>; // 题型配额，如 {single_choice:8, fill_blank:4, answer:8}
  estimatedMinutes?: number;        // 预估时长
}
```

**改动点**：
1. `questionBankService.pickRandomQuestions`：**按 blueprint 配额分桶抽题**（先按知识点逐个取配额 → 再按难度带内洗牌 → 最后按题型配额裁剪），返回前校验"知识点覆盖率 ≥ 80%，不足则 warn"
2. `buildExamPaperTask`（RANDOM 分支）：透传 blueprint，title 可带"（约 X 分钟）"
3. 专项组卷表单（`TaskConfigCenter` 专项 PAPER）：新增「难度分布 易:中:难」三输入（默认 4:4:2）+「目标知识点」多选（候选来自 `weak-points` 接口）
4. 管理端建卷/导入表单：可选难度分布（`QuestionPaper` 加 `blueprint Json?`，导入试卷时可记录）
5. 难度映射沿用项目不变量：Int 1-5 → easy=1-2 / medium=3 / hard=4-5（**注意前端字符串 'medium' 必须映射，勿直传**）

### 模块 C：学习路径规划（对应技能 3，P1）

**C1 训练计划阶段增强（PROFILE）**：
- `trainingPlanData.stages[*]` 每阶段补：`completionCriteria`（可验证完成标准，如"连续 3 题全对且正确率 ≥70%"）、`milestoneQuiz`（里程碑自测题）
- 训练舱阶段切换（foundation→improvement→application）时校验完成标准，未达标提示"回退本阶段重做"

**C2 先修依赖（P1，与 A 联动）**：
- 知识点增加 `prerequisites`（Json 数组），维护入口：管理端题库知识点管理 / AI 会话时自动推导
- 出题/选题优先"先修未掌握"的阻塞点；`blocks_followup` 据此计算

**C3 CUSTOM 目标拆解（P1）**：
- 家长发 CUSTOM 任务时，`createTask` 在组装 aiInstruction 前先调 AI 把 `goal` 拆为 2-3 个阶段目标（降级：不拆，直接原样），存 `config.phasedGoals`
- 训练舱进度条旁显示当前阶段目标（基于 20%/80% 切分点映射）

**C4 训练节奏（P1）**：
- 前端"已 N 天未训练"提示升级为：「本周建议完成 X 题/轮」，由任务 config.questionCount × 剩余天数估算

### 模块 D：合规与口径（所有模块，P0 附带）
- 报告/学期总结/教学建议文案统一遵守：仅作教学参考、聚焦"知识点薄弱"不贴标签、不点名排名
- 组卷导出标注"教师须审核"；不生成/不还原真题（管理端题库导入已有限制，保持）

## 七、风险与边界（需产品确认）

1. **班级维度是最大的"不能做"**：当前是 1v1 平台，无班级/学校/教研员角色。技能 1 的"班级画像、多班对比、备课助手"需要新增班级-学员绑定与教研员端，属产品级扩展，方案**只嵌入个体侧诊断方法论**，班级侧列为 P2 待议。
2. **先修依赖数据冷启动**：`prerequisites` 需要来源（AI 推导或管理端维护），初期可只对高频知识点人工标注，其余留空不影响主流程。
3. **难度分布数据不足**：现网题目 difficulty 标注可能不全，blueprint 配额抽不满时**必须有全库兜底**（沿用 `generateQuestions` 的降级模式，打 warn 日志）。
4. **AI 目标拆解/教学建议的质量**：均须**降级兜底**（失败回退原样），且建议文案只作参考，不承诺效果。
5. **与现有 AI 链路约束冲突检查**：所有新增 AI 调用走 `aiServiceManager.callProviderWithRetry`（本地 120s/远程 30s），不新增硬编码超时；新增 prompt 注意降 token（复用归档总结/学情摘要而非全量历史）。
