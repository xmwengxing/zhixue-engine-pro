# 任务体系与训练舱智能体平台改造方案（设计稿 v1）

> 状态：待用户确认 | 日期：2026-07-29
> 范围：任务发布分类、题库化初测、AI 难度归类、学科化学情报告、训练舱智能体文档与记忆体系

---

## 〇、现状结论（调研摘要）

| 现状 | 与新需求的冲突 |
|---|---|
| `Task` 只有 `mode`（PROFILE/CUSTOM/EXAM_PAPER），无"总任务/专项"概念，subject 埋在 config JSON 里 | 无法区分学科总任务与专项任务，无法按学科索引 |
| PROFILE 模式诊断题由 AI 实时生成（`aiQuestionGeneratorService`），题目不入 `Question` 表 | 与需求 2（初测从题库调用）直接冲突；且 AI 生成题的错题无法进 `ErrorQuestion`（外键指向 Question 表） |
| `Report` 表只有 `sessionId/studentId/taskId/content`，**无 subject、无分类** | 无法按学科归档、无法区分总任务/专项报告 |
| `Question.difficulty` 为 Int(1-5)，但目前多数导入题未设或随意设 | 需要 AI 一键归类 + 判定标准 |
| AI 指令分裂：一级指令在数据库（`SubjectInstruction.systemPrompt`），出题/规划/报告 prompt 硬编码在 `aiPromptBuilder.ts` | 需求 4 要求流程/指令/约束全部可在管理端增删改查 |
| 对话记忆仅会话内（`AIConversation` 最近10条），无跨任务长期记忆 | 需求 4 要求记忆文档 + 历史学情作为可中断/持续依据 |
| `ErrorQuestion` 已有 `subject` 字段 + 艾宾浩斯复习机制 | ✅ 天然支持"错题汇总到一起"，无需改动 |

## 一、任务双轨制：学科总任务 vs 专项攻克任务

### 1.1 数据模型

```prisma
enum TaskCategory {
  SUBJECT_MAIN   // 学科总任务：长期存档，计入学情与学习报告
  SPECIAL        // 专项攻克任务：独立区域、独立报告
}

enum SpecialTaskType {
  UNIT             // 单元专项
  KNOWLEDGE_POINT  // 知识点专项
  ERROR_BOOK       // 错题集专项
}

model Task {
  // ...原有字段...
  category     TaskCategory     @default(SUBJECT_MAIN)
  subject      String?          // 从 config 提升为一级字段（索引）
  specialType  SpecialTaskType? // 仅 SPECIAL 任务
  targetRef    Json?            // 专项目标：{unitIds:[]} 或 {knowledgePoints:[]} 或 {errorQuestionIds:[]}
  @@index([studentId, category, subject])
}
```

- `mode`（PROFILE/CUSTOM/EXAM_PAPER）保留为"出题方式"维度，与 `category`（任务性质）正交。
- 错题重做（`studentErrorService.createRetrySession` 现在建的临时 CUSTOM 任务）统一收编为 `SPECIAL + ERROR_BOOK`。

### 1.2 隔离规则

| 维度 | 学科总任务 | 专项攻克任务 |
|---|---|---|
| 发布入口 | 任务中心"学科总任务" Tab | "专项攻克" Tab（选单元/知识点/错题集） |
| 查询区域 | 家长端/学员端主任务列表 | 独立"专项攻克"列表页 |
| 学习报告 | 计入学科学情档案（§三），生成学科总报告 | 独立专项报告，仅关联到该专项目标 |
| 学情统计 | ✅ 更新 `SubjectLearningState`（IRT、知识点掌握度） | 仅更新对应知识点的掌握度明细，**不改写总体学情结论**（可作为佐证附注） |
| 错题 | → `ErrorQuestion`（按 subject 汇总） | → `ErrorQuestion`（同一个池子，✅汇总一起） |
| 数量约束（建议） | 同一学科同时只允许 1 个进行中 | 不限个数 |

### 1.3 前端改动

- `TaskConfigCenter.tsx`：顶层先选任务大类（总任务/专项），再选出题方式。专项类增加目标选择器（复用已有的教材/单元选择器 `TextbookUnitSelector`，知识点从学情档案的薄弱点列表带出，错题集从错题本多选）。
- 家长端/学员端任务列表、`TaskReportCenter.tsx` 拆分双区。

## 二、初测题库化 + AI 难度归类

### 2.1 初测来源改造

发布任务时"初始测试题"一律从题库调用，两种方式：

1. **手动模式**：家长直接选一份已发布试卷（QuestionPaper，可按教材/单元/试卷类型筛选——上一阶段已做好的分类），或按 单元+难度+题量 条件筛题预览后确认。
2. **AI 自动模式**：AI 读取学员信息（年级、教材版本、`SubjectLearningState` 薄弱点、近期错题分布）→ 输出一组**筛题条件**（单元集合、难度分布如 5:3:2、题量）→ 后端用 `pickRandomQuestions` 从题库抽题 → 返回预览给家长确认后发布。
   - 关键设计：**AI 只产出筛题条件，不产出题目本身**——可控、可审计、永不超纲。

**兜底策略（需你决策，见 §五 Q3）**：题库存量不足时，A) 提示家长换条件/补充导入；或 B) 允许 AI 生成补齐缺口并打上 `source=AI_GENERATED` 标记入库（入库后就能归集错题）。建议 B，但默认关闭，管理端开关控制。

- PROFILE 模式的诊断阶段（`getNextDiagnosticQuestion`）同步改为从预抽的题库题集合中出题，废弃逐题 AI 生成路径（保留代码但断开入口）。
- 附带修复一个现存缺陷：AI 生成题不入 Question 表导致 PROFILE 模式错题无法进错题本——题库化后自动解决。

### 2.2 AI 一键难度归类

**入口**：题库管理页新增「AI 归类难度」按钮（可全量/仅未标注/按试卷范围），后台批量任务逐题调用 AI，写回 `Question.difficulty`，并记录 `difficultyMeta Json`（AI 给出的归类理由、置信度、归类时间、标准版本号），低置信度题目进入"待人工复核"列表。

**判定标准（作为 AI 指令，存入管理端可编辑的智能体文档 §四）**——基于教育测评通行做法（难度系数 P 值 + 布鲁姆认知层级 + 中考 7:2:1 结构）设计五级标准，对齐现有 `difficulty Int 1-5`：

| 等级 | 对应难度系数 P | 认知层级（布鲁姆） | 通用特征 |
|---|---|---|---|
| 1 基础 | ≥0.85 | 记忆 | 单一知识点直接再现，一步作答 |
| 2 较易 | 0.70–0.85 | 理解 | 单知识点简单变形，1–2 步 |
| 3 中等 | 0.55–0.70 | 应用 | 关联 2–3 个知识点，2–3 步推导，教材变式情境 |
| 4 较难 | 0.40–0.55 | 分析 | 跨章节综合，3–5 步推理，真实情境/隐含条件 |
| 5 难 | <0.40 | 评价/创造 | 压轴题级，多解法/开放性/竞赛倾向 |

**数学附加判据**：推理步骤数、涉及知识点数、是否含参/分类讨论、计算量、几何辅助线层数、是否动点/存在性问题（4-5 级典型特征）。

**英语附加判据**：词汇范围（课标 1600 词内=低档，超纲词占比>3%=升档）、句式复杂度（从句嵌套层数）、题型基准（听力/单选基础题基线 1-2 级，完形/语法填空基线 3 级，阅读推断题/书面表达高分档基线 4-5 级）、语篇类型（记叙文易 → 说明/议论文难）。

**校准闭环（建议）**：上线后用真实作答数据回算实测难度系数 P=平均得分率，与 AI 标定偏差 ≥1 级的题自动进复核列表，形成"AI 预标 → 实测校准"循环。

## 三、学科化学情与学习报告

### 3.1 新增学科学情档案（核心）

```prisma
model SubjectLearningState {   // 每生每科一条，持续滚动更新
  id            String  @id
  studentId     String
  subject       String
  irtTheta      Float?          // 能力估计值（从会话 IRT 汇聚）
  masteryMap    Json            // {知识点: {score:0-100, trend, lastAt}}
  weakPoints    Json            // 薄弱点排序列表
  errorStats    Json            // 错题分布快照
  taskHistory   Json            // 总任务履历摘要 [{taskId, title, 完成度, 得分}]
  updatedAt     DateTime
  @@unique([studentId, subject])
}
```

- 更新时机：学科总任务的每个会话结束时增量合并；专项任务只更新 `masteryMap` 中对应知识点并加注 `source:'special'`。
- 这张表就是家长/学员"学情页"的数据源，也是 AI 学科老师和 AI 自动选题的调用入口（一个 service 函数 `getSubjectState(studentId, subject)` 全端复用）。

### 3.2 Report 改造

- `Report` 增加 `subject String?`、`category TaskCategory`、`specialType?` 字段；存量数据迁移脚本按 task.config.materialNodeIds 回溯 SUBJECT 补 subject（无法回溯的标"综合"）。
- 报告内容结构统一为：总结 → 能力分析（知识点雷达）→ 错因分析 → 建议 → **本学科历史对比**（新增，取自 SubjectLearningState 趋势）。
- 前端：家长端 `TaskReportCenter` 与学员端报告页改为 **学科 Tab → (总任务报告 | 专项报告) 双区**；新增"学科学情总览页"（雷达图 + 掌握度趋势 + 错题分布），家长/学员共用组件、按角色控制入口。
- 两套并存的报告生成器（旧 Markdown 版 + 新 `reportGenerationService`）借机收敛为一套（新版）。

## 四、训练舱智能体平台：文档体系 + 记忆机制

### 4.1 智能体文档模型（管理员增删改查）

```prisma
enum AgentDocType {
  FLOW          // 系统化流程（训练舱各阶段该怎么走）
  INSTRUCTION   // 内部指令（角色设定、教学法、语气）
  CONSTRAINT    // 约束（红线：不代答、不超纲、不讨论无关话题…）
  STANDARD      // 判定标准（如 §2.2 难度归类标准）
  MEMORY_SPEC   // 记忆文档撰写规范（AI 写记忆时遵循的格式）
}

model AgentDocument {
  id        String       @id
  type      AgentDocType
  subject   String?      // null=全局通用，非空=学科专属（学科覆盖全局）
  title     String
  content   String       @db.Text   // Markdown
  version   Int          @default(1)
  enabled   Boolean      @default(true)
  priority  Int          // 注入顺序
  updatedBy String
  updatedAt DateTime
}
```

- 现有 `SubjectInstruction.systemPrompt` 收编为 `INSTRUCTION` 类文档（迁移脚本），`aiPromptBuilder.ts` 里硬编码的流程性 prompt 逐步抽出为 `FLOW` 文档，代码里只留模板骨架和变量拼装。
- 管理端新页面「智能体配置」：按类型/学科分组的文档列表 + Markdown 编辑器 + 版本号 + 启用开关。初始化时内置一套默认文档（种子脚本），管理员在其上修改。

### 4.2 学员记忆文档

```prisma
model StudentMemory {
  id        String   @id
  studentId String
  subject   String?  // null=全局记忆（学习习惯/性格），非空=学科记忆
  content   String   @db.Text  // Markdown，AI 维护，限长（如 4000 字）
  version   Int
  updatedAt DateTime
  @@unique([studentId, subject])
}
model StudentMemoryLog {  // 每次修订的快照，便于审计回滚
  id, memoryId, sessionId, diff/content, createdAt
}
```

- **写入时机**：每个训练会话结束（或中断）时，AI 按 `MEMORY_SPEC` 规范生成"本次会话记忆增量"（掌握变化、有效讲解方式、情绪/习惯观察、未完成事项），与旧记忆合并压缩，超长时 AI 自我摘要。
- **管理端可增删改查**（智能体配置页的"学员记忆"子页），家长端只读可见（建议，见 Q4）。

### 4.3 披露给 AI 的方式：分层上下文装配器

新增 `agentContextBuilder.ts`，每次 AI 调用（出题条件生成/规划/引导对话/批改/报告）统一装配，按优先级注入并做 token 预算裁剪：

```
L1 约束 CONSTRAINT（全局+学科）        ← 永不裁剪
L2 角色指令 INSTRUCTION（学科覆盖全局）
L3 流程文档 FLOW（仅当前阶段的段落）
L4 学员记忆 StudentMemory（全局+该学科）
L5 学科学情摘要 SubjectLearningState（薄弱点TOP5+近期趋势，程序生成摘要而非全量）
L6 任务配置与会话状态（trainingProgress、最近对话）
```

**可中断/持续**：会话中断后重进，L4+L5+L6 三层即可完整恢复语境——"上次练到勾股定理第 3 题连错 2 次，已下钻到直角三角形判定"这类状态由 L6 承载，跨任务的"这孩子图形题薄弱、喜欢例题式讲解"由 L4 承载。

## 五、需要你决策的问题

| # | 问题 | 我的建议 |
|---|---|---|
| Q1 | 学科总任务同一学科是否限制"同时只有 1 个进行中"？ | 限制。长期任务语义下多个并行会污染学情归因 |
| Q2 | 难度分级用 1-5 五级（对齐现有字段）还是 易/中/难 三级？ | 五级。信息量更大，前端展示时可折叠为三档（1-2易/3中/4-5难） |
| Q3 | 题库存量不足时是否允许 AI 生成补齐（生成题入库、打标记）？ | 允许但默认关闭，管理端开关。前期你批量导入试卷后基本用不到 |
| Q4 | 学员记忆文档对家长/学员是否可见？ | 家长只读可见（透明度），学员不可见（避免标签化心理暗示） |
| Q5 | 专项任务是否也走"初测→规划→训练→终测"完整流程？ | 简化为"直接训练→小结"，错题集专项复用现有重做+艾宾浩斯机制 |
| Q6 | 旧数据兼容：存量任务/报告统一标为 SUBJECT_MAIN 并回溯 subject，无法回溯的标"综合"，可接受？ | 是 |

## 六、实施顺序（确认后执行）

1. **P1 数据层**：schema 迁移（Task 分类字段、Report subject、SubjectLearningState、AgentDocument、StudentMemory）+ 存量迁移脚本 + 智能体默认文档种子
2. **P2 题库化初测**：手动选卷/条件筛题 + AI 条件生成 + 诊断阶段改造 + AI 难度归类按钮与批量任务
3. **P3 任务双轨**：发布界面改造、双区列表、专项目标选择器、错题重做收编
4. **P4 学情报告**：SubjectLearningState 更新管线、报告学科化、学情总览页（家长/学员）
5. **P5 智能体平台**：agentContextBuilder、prompt 抽离入库、管理端智能体配置页、记忆读写闭环
6. **P6 回归**：类型检查、种子数据、端到端验证（发布→初测→训练→中断恢复→报告→学情）

每阶段独立可验证，P1 是所有后续的前置。预计新增/修改约 25–30 个文件。
