# 积分商城（愿望单）体系 V2 — 设计方案

> 目标：全面重构积分机制——**所有任务均可获得积分，1 积分 = 1 元人民币**；完整获取体系 +
> 参与度惩罚机制（多次未完成每日题量、单词训练中断多天等）；**准确率/成绩不参与惩罚**，
> 避免打击自信心。本方案借鉴 K12 班级积分制成熟做法（正向激励为主、加扣比 ≥5:1、
> 防负分、将功补过、申诉、周反馈）。

---

## 一、设计总原则（6 条，对齐 K12 最佳实践）

| # | 原则 | 说明 |
|---|---|---|
| 1 | **正向激励为主** | 加扣比例 ≥ 5:1，积分制核心是"鼓励参与"，不是管束 |
| 2 | **只罚参与度、不罚成绩** | 扣分仅针对"未完成训练量/中断/拖延终测"；准确率、考试成绩、错题数**一律不扣** |
| 3 | **余额不扣成负** | 扣到 0 分即止；0 分学员有"补位任务"（如完成 1 个专项任务）快速回血，避免破罐破摔 |
| 4 | **规则透明可预期** | 前端"积分规则"页明示全部加减项与阈值；每周自动汇总一次（周报） |
| 5 | **提醒先行、惩罚留台阶** | 扣分前先红点/通知提醒；**连续 N 天**才触发；提供"将功补过"（申诉/补救任务） |
| 6 | **即时反馈** | 每次获得/扣除积分都有流水 + 原因，任务卡片上显示可获积分提示 |

---

## 二、积分获取体系（全任务覆盖）

> 防刷原则：同类型奖励有每日/每会话上限；"达标"以已实现的 dailyGoal 判定（题量或时长任一达标）。

### A. 学科总任务（每日训练 + 阶段 + 终测）

| 行为 | 积分 | 频次/说明 |
|---|---|---|
| 每日训练达标（dailyGoal 完成） | **+5** | 每天 1 次（以 DailyTrainingRecord.todayMet 判定） |
| 连续达标 7 天 | **+10** | 额外奖励（习惯养成），断档清零重计 |
| 周满勤（7 天每天至少训练 1 次） | **+20** | 每周 1 次 |
| 完成引导训练某阶段（基础/提升/应用） | **+10** | 每阶段 1 次 |
| 参加期末测试（提交终测） | **+20** | 不论成绩 |
| 终测达标（正确率 ≥ goalScore） | **+30** | 额外奖励（达成本身是激励，不扣分） |

### B. 专项攻克任务（单元/知识点/错题本/组卷）

| 行为 | 积分 | 说明 |
|---|---|---|
| 完成 1 题（提交即算，无论对错） | **+1** | 参与即有 |
| 一次性完成整卷（PAPER/组卷） | **+10** | 卷完成时发放 |
| 错题重练正确（ERROR_RETRY） | **+2** | 沿用现有，巩固错题 |

### C. 英语单词任务（听写/默写）

| 行为 | 积分 | 说明 |
|---|---|---|
| 完成 1 词（逐词提交） | **+1** | 参与即有（听写/默写均计） |
| 完成整轮（roundSize 词 + 短语填空） | **+10** | 轮完成时发放 |
| 复习旧词正确（WordMistake level 提升） | **+2** | 到期复习答对 |

### D. 通用/引导

| 行为 | 积分 | 说明 |
|---|---|---|
| AI 引导后独立解出（GUIDED_SOLVE） | **+3** | 沿用现有 |
| 完成错题重练任务 | **+2/题** | 沿用现有 |
| 新学员开户基础分 | **+50** | 初始余额（避免起点为 0 挫败感） |

> 估算收益节奏：坚持每天达标 + 专项 ≈ 每周 **50~80 分**，一个月 200~320 元等值积分，可兑换有意义的愿望（文具、课外书、小礼物）。

## 三、积分惩罚体系（仅参与度）

> 铁律：**准确率、考试分数、错题数量不参与任何扣分**。扣分只针对"没参与"。

| 场景 | 扣分 | 触发规则 |
|---|---|---|
| 学科总任务：连续 3 天未完成每日训练量 | **-10** | 每满 3 天扣一次（3/6/9…），提醒先行（第 2 天起红点提醒） |
| 单词任务：连续 3 天未训练 | **-5** | 按最近训练时间，同上提醒先行 |
| 引导训练完成但 7 天未参加终测（拖延） | **-10** | 第 5 天提醒，第 7 天扣 |
| 账户余额 | — | **扣到 0 为止，不为负** |

**缓冲与补救（防破罐破摔）**：
1. **提醒先行**：第 2 天/第 5 天先红点 + 站内通知，给机会；
2. **将功补过**：被扣分后 3 天内完成 1 个专项任务，**返还 50% 扣分**（如扣 10 还 5）；
3. **申诉**：对扣分有异议，学员提交申诉 → 家长审核（系统记录申诉原因与结果）；
4. **补位任务**：余额 0 的学员在任务中心看到"今日补位任务"引导（完成 1 个专项任务赚回基础分）。

**技术实现（惰性结算，不依赖定时任务）**：
- 每次答题/训练提交时，顺带结算该任务"上次训练至今未达标天数"→ 满足阈值且未扣过则扣分（PointsTransaction 记 `participation` 类型 + relatedId = 任务，防重复扣）；
- 连续达标/满勤同样惰性结算（达标当天检查连续天数）。

## 四、愿望单兑换（1 积分 = 1 元）

现有 `Wish` 表已支持（CUSTOM/现金类型 + requiredPoints + 家长审核流），V2 增强：

1. **价值对齐**：`requiredPoints` 数值 = 人民币金额（20 积分 = 20 元愿望），兑换后家长线下兑现；
2. **兑换门槛校验**：余额 ≥ requiredPoints 才能提交；兑换成功扣减余额（现有 deductWishPoints）；
3. **余额与流水**：积分商城头部展示当前余额（= 总入 - 总出，流水按类型分组展示）；
4. **家长端积分总览**：孩子的积分余额/流水/扣分明细/申诉列表（审核申诉）；
5. **愿望分级**（借鉴 K12 三层奖励）：
   - 低门槛（≤20 分）：小文具、免一次作业（与家长约定）
   - 中档（21~100 分）：课外书、玩具、一次外出
   - 荣誉档（>100 分）：大愿望（生日礼物、游乐园等），家长审核通过即可
6. **家长可手动调整积分**（±）：教学奖励/家规奖惩（记录原因，避免与系统自动分混淆，type=PARENT_ADJUST）。

## 五、数据与技术设计

### 5.1 Prisma 变更
- `PointsTransaction.type` 枚举扩展：
  ```
  DAILY_GOAL_MET      // 每日训练达标
  STREAK_BONUS        // 连续达标奖励
  WEEKLY_ATTENDANCE   // 周满勤
  STAGE_COMPLETE      // 阶段完成
  FINAL_EXAM_DONE     // 参加终测
  FINAL_EXAM_PASS     // 终测达标
  WORD_ANSWERED       // 单词作答
  WORD_ROUND_DONE     // 单词轮完成
  WORD_REVIEW_CORRECT // 单词复习正确
  SIGNUP_BONUS        // 开户基础分
  PARENT_ADJUST       // 家长手动调整
  PARTICIPATION_PENALTY // 参与度扣分
  PENALTY_RETURN      // 将功补过返还
  WISH_REDEEM         // 愿望兑换（已有）
  TASK_COMPLETE / ERROR_RETRY / GUIDED_SOLVE（已有）
  ```
- `PointsTransaction` 增加 `memo String?`（扣分/调整原因，展示与申诉依据）

### 5.2 积分引擎（pointsEngineService）
- `reward(taskId, studentId, type, amount, relatedId?, memo?)`：统一入账（复用现有 addTransaction 行锁 + balance 快照），**幂等防刷**（同 taskId+type+date 唯一校验）
- `checkParticipationPenalties(taskId, studentId)`：惰性结算扣分（提醒先行、不扣负、防重复）
- 挂载点：每日达标判定（dailyTrainingService）、单词逐词提交（wordTaskController）、单词轮完成、训练阶段切换、终测提交（submitFinalExam）、专项任务完成

### 5.3 接口（学员端）
| 接口 | 说明 |
|---|---|
| `GET /student/points/balance` | 余额 + 总入总出 |
| `GET /student/points/transactions?type=&page=` | 流水明细（分类型筛选） |
| `GET /student/points/rules` | 积分规则页数据（全部加减项 + 阈值） |
| `POST /student/points/appeal/:txId` | 扣分申诉（提交原因） |
| 愿望单接口沿用（Wish CRUD + redeem） | 兑换门槛校验增强 |

### 5.4 家长端
| 接口 | 说明 |
|---|---|
| `GET /parent/children/:id/points` | 积分总览（余额/流水/本周变化） |
| `POST /parent/children/:id/points/adjust` | 手动调整（±，附原因） |
| `POST /parent/wishes/:id/review` + 申诉审核 | 愿望审核（已有）+ 扣分申诉处理 |

### 5.5 前端
- **学员积分商城页**（改造 PointsWishMall）：头部余额卡片 + 流水 Tab + 积分规则折叠页 + 愿望列表（显示所需积分/余额）＋ 兑换弹窗
- **任务卡片**：显示本任务"完成后可得积分"提示（如"每日达标 +5"）
- **家长积分总览**：孩子积分趋势（近 30 天）、扣分明细（含原因）、申诉处理
- 暗色主题，与现有 UI 一致

## 七、需要你确认的决策点

1. **数值节奏**：默认节奏"每天达标 +5、连 7 天 +10、周满勤 +20、终测 +20/达标 +30"——偏保守还是合适？（决定孩子攒一个 100 分大愿望约需 1~2 个月）
2. **基础分 50**：新学员开户送 50 分（起点不寒酸），是否要？金额太高可改 20。
3. **惩罚阈值**：连续 3 天扣 10 分（学科）/扣 5 分（单词）、终测拖延 7 天扣 10——幅度是否合适？（建议从轻：先 -5 试运行）
4. **家长手动调分**：支持家长 ± 调整（可设"每日限额"防乱调），是否启用？
5. **扣分是否需要家长确认**：自动扣分立即生效 + 申诉兜底（家长处理申诉），还是**扣分先挂起、家长确认后生效**？（后者更稳但增加家长负担）
6. **补位任务**：余额 0 时展示"完成 1 个专项任务 +5"引导——是否要？

确认后按第六节顺序实施。
