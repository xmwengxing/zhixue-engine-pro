# 试卷转换与入库标准化工作流

> 常态化任务：把本地试卷库（PDF/DOCX）批量转换为结构化题目并入库，支持生成离线数据包分发到任意生产环境。
> 适用批次：八年级/试卷与习题（已跑通）、九年级/试卷与习题（下一批，改根路径即可）。
> 更新：2026-08-19（首次标准化）

---

## 0. 流程总览

```
A 目录准备 → B 批量转换 → C OCR 补跑 → D 图片提取 → E 入库 → F 离线数据包
   (一次)      (文本层)     (扫描件)     (题级图)     (配对+幂等)   (分发)
```

**产物目录**：`开发文档/试卷转换产物/`（progress 断点 + 每卷 JSON + 报告 + OCR 额度）

## 1. 前置条件

| 项 | 说明 |
|---|---|

| 飞桨 OCR | 本地 DB `ocr_providers` 已配 PaddleOCR-VL（token）；**单文件上限 100 页**、**日额度 20000 页** |

## 2. 步骤 A：目录准备（一次性）

1. 确认根路径：脚本常量 `ROOT`（convert）/ `PAPER_ROOT`（import/pack）→ 新批次年级路径
2. 清理空目录：`find <学科目录> -type d -empty -delete`（清单先导出留档）
3. **⚠️ 文件名规范**：转换以「扫描时实际文件名」为准；整理目录时**不要再改文件名**（会导致旧 progress 全部失效）

## 3. 步骤 B：批量转换（文本层，快）

```bash
cd backend
for s in 历史 语文 英语 数学 物理; do
  node scripts/convert-papers-batch.mjs --subject $s --limit 99999 \
    --progress "E:/Projects/zhixue-engine-pro/开发文档/试卷转换产物/progress-full2-$s.json"
done
```

- 去双后缀命名（`xxx.docx.pdf` → `xxx`，循环剥 `.pdf/.docx/.doc`）
- 文本层提取（pdf-parse/mammoth，**零 OCR**）；「逐字断行 PDF」自动拼接（题号/选项/【标记 为块起始）
- 「解析版」文档标记 `skipped-doc`（答案来源，不独立成题）
- 扫描件标记 `pending-ocr`（主流程不阻塞）
- 断点续传：progress JSON，重跑自动跳过已完成

## 4. 步骤 C：OCR 补跑（扫描件）

```bash
for s in 历史 语文 英语 数学 物理; do
  node scripts/convert-papers-batch.mjs --subject $s --limit 99999 --retry-errors \
    --progress "E:/Projects/zhixue-engine-pro/开发文档/试卷转换产物/progress-full2-$s.json"
done
```

- 只重试 `error/text-empty/pending-ocr`；**页数 > 100 跳过**（飞桨单文件上限，超长册放弃）
- 额度控制：`ocr-usage.json` 累计页数，耗尽自动中断（exit 3）
- 参数说明：`--retry-errors`（重试失败+扫描件）；`--ocr-only`（只跑扫描件）

## 5. 步骤 D：图片提取（题级区域渲染，方案 A）

```bash
python scripts/extract-question-images.py \
  --progress "E:/Projects/zhixue-engine-pro/开发文档/试卷转换产物/progress-full2-SUBJ.json" \
  --out backend/uploads/questions --subjects 数学,物理
```

- pymupdf 按题号块定位 → 渲染「题号→下题号」区域 PNG（150dpi）→ 非白判断跳过文字题
- 幂等：按 map.json 的 `sourceFile` 匹配（已生成的卷跳过）
- 产物：`uploads/questions/<卷ID>/q<N>.png` + `map.json`（题号→图路径）

## 6. 步骤 E：入库（配对合并 + 图关联 + 幂等）

```bash
node scripts/import-papers-to-db.mjs --subjects 历史,语文,英语,数学,物理   # 正式入库
node scripts/import-papers-to-db.mjs --subjects 数学 --dry                 # 只检查不写库
```

- **答案/解析配对**：原卷版 ↔ 解析版按「去版后缀文件名」匹配（全局索引，跨目录）；
  解析版 `parseAnswerFile` 提取 {题号→答案/解析} 回填（题号优先 + 顺序兜底）
- **图关联**：imgIndex（启动遍历 map.json 按 sourceFile 匹配，ID 无关）
- **幂等**：`sourceFile` 已存在跳过；空题卷跳过；断点 `progress-import.json`（dry 不写断点）
- 入库结构：Question（content={stem, options, correctAnswer, explanation, image}，type/difficulty 映射）
  + QuestionPaper（title=去后缀名，categoryId=期中/期末/专项/单元/通用 目录，paperType 映射）
  + QuestionPaperItem（题-卷关联，order）

## 7. 步骤 F：离线数据包（打包 + 一键导入）

**打包**（本机）：
```bash
node scripts/pack-papers.mjs --out "开发文档/试卷转换产物/papers-package-v1"
tar -czf papers-package-v1.tar.gz -C <父目录> papers-package-v1
```

包结构：
```
papers-package-v1/
├── metadata.json    # 版本/学科/卷数/题数/图数
├── papers/<学科>/<卷ID>.json   # 每卷最终形态（题目+答案+解析+图引用，已配对）
├── images/          # 题图（扁平）
└── import.sh        # 一键导入脚本
```

**导入**（任意目标环境：本机/服务器容器/新部署）：
```bash
# 1. 上传 tar.gz 并解压
# 2. 后端目录（有 Prisma/DB 连接）执行：
bash import.sh <backend目录>
#   等价于：
node scripts/import-papers-to-db.mjs --package <包目录>
```
- `--package` 模式：读包内卷 JSON 直接写库（幂等，无需重转/重 OCR/重配对）
- 生产环境需先把 `images/` 放入后端 `uploads/questions/`（content.image 指向 `/uploads/questions/...`）

## 9. 故障排查（踩过的坑）

| 现象 | 原因 | 处理 |
|---|---|---|
| 配对答案率低（<20%） | 源数据本身无答案（原卷版分离结构）或解析版题号不匹配 | 顺序兜底已启用；仍低属数据源限制，可后续按题干文本匹配优化 |
| 图片提取 0 张 | 全部幂等跳过（旧图复用）或题目无图 | 属正常；检查 uploads/questions 已有图 |
| 入库题数比转换少 | 同名卷合并（key 含目录已修复）或空题卷跳过 | 核对日志「空题跳过」清单 |
| OCR 全部失败 | 文件名/路径变更 | 重新扫描转换（progress-full2） |
| 断点污染（入库跳过） | progress-import.json 残留（dry 也会写） | 已修（dry 不写断点）；手工删除断点后重跑 |
