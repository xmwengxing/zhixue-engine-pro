## 前置要求

### 必需软件

- Docker Engine 20.10+
- Docker Compose 2.0+

### 安装 Docker

**Linux (Ubuntu/Debian):**
```bash
# 安装 Docker
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh

# 安装 Docker Compose
sudo apt-get update
sudo apt-get install docker-compose-plugin

# 验证安装
docker --version
docker compose version
```

**macOS:**
```bash
# 使用 Homebrew 安装
brew install --cask docker

# 或下载 Docker Desktop
# https://www.docker.com/products/docker-desktop
```

**Windows:**
```powershell
# 下载并安装 Docker Desktop
# https://www.docker.com/products/docker-desktop

# 验证安装
docker --version
docker compose version
```

## 快速开始

### 1. 克隆项目

```bash
git clone <repository-url>
cd training-platform
```

### 2. 配置环境变量

创建 `.env` 文件（用于 Docker Compose）：

```bash
# 复制示例文件
cp .env.example .env

# 编辑配置
nano .env
```

最小配置示例：

```env
# JWT 密钥（必须修改）
JWT_SECRET=your-strong-secret-key-at-least-32-characters-long
JWT_REFRESH_SECRET=your-strong-refresh-secret-key-at-least-32-characters

# 会话密钥（必须修改）
SESSION_SECRET=your-strong-session-secret-key

# AI 服务配置（可选）
OPENAI_API_KEY=sk-your-openai-api-key
CLAUDE_API_KEY=sk-ant-your-claude-api-key

# 前端 API 地址
VITE_API_BASE_URL=http://localhost:3000/api
```

### 3. 启动服务

```bash
# 构建并启动所有服务
docker compose up -d

# 查看日志
docker compose logs -f

# 查看服务状态
docker compose ps
```

### 4. 初始化数据库

```bash
# 运行数据库迁移
docker compose exec backend npx prisma migrate deploy

# （可选）填充测试数据
docker compose exec backend npx tsx src/scripts/seed-test-data.ts
```

### 5. 访问应用

- 前端应用：http://localhost
- 后端 API：http://localhost:3000
- API 健康检查：http://localhost:3000/health

## 配置说明

### Docker Compose 服务

项目包含以下服务：

#### 1. PostgreSQL 数据库 (`postgres`)

- **镜像**: `postgres:15-alpine`
- **端口**: `5432:5432`
- **数据卷**: `postgres_data`
- **健康检查**: 每 10 秒检查一次

**环境变量：**
- `POSTGRES_USER`: 数据库用户名
- `POSTGRES_PASSWORD`: 数据库密码
- `POSTGRES_DB`: 数据库名称

#### 2. Redis 缓存 (`redis`)

- **镜像**: `redis:7-alpine`
- **端口**: `6379:6379`
- **数据卷**: `redis_data`
- **持久化**: AOF 模式

#### 3. 后端 API (`backend`)

- **构建**: `./backend/Dockerfile`
- **端口**: `3000:3000`
- **数据卷**: 
  - `backend_logs`: 日志文件
  - `backend_uploads`: 上传文件
- **依赖**: postgres, redis

**环境变量：** 参见 `backend/ENV_CONFIG.md`

#### 4. 前端应用 (`frontend`)

- **构建**: `./frontend/Dockerfile`
- **端口**: `80:80`
- **Web 服务器**: Nginx
- **依赖**: backend

#### 5. Nginx 反向代理 (`nginx`) - 可选

- **镜像**: `nginx:alpine`
- **端口**: `8080:80`
- **配置**: `./nginx/`
- **用途**: 统一入口，API 和前端代理

**启用方式：**
```bash
docker compose --profile with-nginx up -d
```

### 数据卷

持久化数据存储：

- `postgres_data`: PostgreSQL 数据
- `redis_data`: Redis 数据
- `backend_logs`: 后端日志
- `backend_uploads`: 上传文件

### 网络

所有服务运行在 `training-platform-network` 桥接网络中，服务间可以通过服务名互相访问。

## 常用命令

### 服务管理

```bash
# 启动所有服务
docker compose up -d

# 启动特定服务
docker compose up -d backend

# 停止所有服务
docker compose stop

# 停止并删除容器
docker compose down

# 停止并删除容器、网络、数据卷
docker compose down -v

# 重启服务
docker compose restart

# 重启特定服务
docker compose restart backend
```

### 日志查看

```bash
# 查看所有服务日志
docker compose logs

# 实时查看日志
docker compose logs -f

# 查看特定服务日志
docker compose logs backend

# 查看最近 100 行日志
docker compose logs --tail=100 backend
```

### 服务状态

```bash
# 查看服务状态
docker compose ps

# 查看服务详细信息
docker compose ps -a

# 查看资源使用情况
docker stats
```

### 进入容器

```bash
# 进入后端容器
docker compose exec backend sh

# 进入数据库容器
docker compose exec postgres psql -U training_user -d training_platform

# 进入 Redis 容器
docker compose exec redis redis-cli
```

### 数据库操作

```bash
# 运行数据库迁移
docker compose exec backend npx prisma migrate deploy

# 生成 Prisma Client
docker compose exec backend npx prisma generate

# 查看数据库状态
docker compose exec backend npx prisma migrate status

# 重置数据库（危险操作！）
docker compose exec backend npx prisma migrate reset
```

### 构建和更新

```bash
# 重新构建镜像
docker compose build

# 重新构建特定服务
docker compose build backend

# 不使用缓存重新构建
docker compose build --no-cache

# 拉取最新镜像
docker compose pull

# 更新并重启服务
docker compose up -d --build
```

## 故障排查

### 1. 服务无法启动

**检查日志：**
```bash
docker compose logs backend
docker compose logs frontend
```

**常见原因：**
- 端口被占用
- 环境变量配置错误
- 依赖服务未就绪

**解决方法：**
```bash
# 检查端口占用
netstat -tulpn | grep :3000
netstat -tulpn | grep :80

# 验证环境变量
docker compose config

# 重新启动依赖服务
docker compose restart postgres redis
```

### 2. 数据库连接失败

**检查数据库状态：**
```bash
docker compose ps postgres
docker compose logs postgres
```

**测试连接：**
```bash
docker compose exec postgres pg_isready -U training_user
```

**解决方法：**
```bash
# 重启数据库
docker compose restart postgres

# 检查数据库日志
docker compose logs postgres --tail=50
```

### 3. 前端无法访问后端 API

**检查网络连接：**
```bash
# 从前端容器 ping 后端
docker compose exec frontend ping backend

# 检查后端健康状态
curl http://localhost:3000/health
```

**检查 CORS 配置：**
- 确保后端 `CORS_ORIGIN` 配置正确
- 检查前端 `VITE_API_BASE_URL` 配置

### 4. 容器频繁重启

**查看重启原因：**
```bash
docker compose ps
docker compose logs --tail=100 <service-name>
```

**常见原因：**
- 健康检查失败
- 内存不足
- 应用崩溃

**解决方法：**
```bash
# 增加资源限制
# 在 docker-compose.yml 中添加：
# deploy:
#   resources:
#     limits:
#       memory: 512M
#     reservations:
#       memory: 256M

# 调整健康检查参数
# healthcheck:
#   interval: 60s
#   timeout: 30s
#   start_period: 60s
```

### 5. 数据丢失

**检查数据卷：**
```bash
docker volume ls
docker volume inspect training-platform_postgres_data
```

**备份数据：**
```bash
# 备份数据库
docker compose exec postgres pg_dump -U training_user training_platform > backup.sql

# 恢复数据库
docker compose exec -T postgres psql -U training_user training_platform < backup.sql
```

## 生产环境部署

### 1. 安全配置

**生成强密钥：**
```bash
# 生成 JWT 密钥
openssl rand -base64 32

# 生成会话密钥
openssl rand -base64 32
```

**配置环境变量：**
```env
NODE_ENV=production
JWT_SECRET=<生成的强密钥>
JWT_REFRESH_SECRET=<生成的强密钥>
SESSION_SECRET=<生成的强密钥>
```

### 2. 使用 HTTPS

**使用 Let's Encrypt：**
```bash
# 安装 Certbot
sudo apt-get install certbot

# 获取证书
sudo certbot certonly --standalone -d your-domain.com

# 配置 Nginx 使用证书
# 在 nginx/conf.d/default.conf 中添加 SSL 配置
```

**Nginx SSL 配置示例：**
```nginx
server {
    listen 443 ssl http2;
    server_name your-domain.com;

    ssl_certificate /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;
    
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers on;
    
    # ... 其他配置
}

# HTTP 重定向到 HTTPS
server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$server_name$request_uri;
}
```

### 3. 资源限制

在 `docker-compose.yml` 中添加资源限制：

```yaml
services:
  backend:
    deploy:
      resources:
        limits:
          cpus: '1.0'
          memory: 1G
        reservations:
          cpus: '0.5'
          memory: 512M
```

### 4. 日志管理

配置日志轮转：

```yaml
services:
  backend:
    logging:
      driver: "json-file"
      options:
        max-size: "10m"
        max-file: "3"
```

### 5. 监控和告警

**使用 Docker Stats：**
```bash
docker stats
```

**集成 Prometheus + Grafana：**
- 添加 Prometheus 导出器
- 配置 Grafana 仪表板
- 设置告警规则

### 6. 备份策略

**自动备份脚本：**
```bash
#!/bin/bash
# backup.sh

DATE=$(date +%Y%m%d_%H%M%S)
BACKUP_DIR="/backups"

# 备份数据库
docker compose exec -T postgres pg_dump -U training_user training_platform > "$BACKUP_DIR/db_$DATE.sql"

# 备份上传文件
docker compose exec backend tar czf - /app/uploads > "$BACKUP_DIR/uploads_$DATE.tar.gz"

# 删除 7 天前的备份
find $BACKUP_DIR -name "*.sql" -mtime +7 -delete
find $BACKUP_DIR -name "*.tar.gz" -mtime +7 -delete
```

**设置定时任务：**
```bash
# 编辑 crontab
crontab -e

# 每天凌晨 2 点备份
0 2 * * * /path/to/backup.sh
```

## 性能优化

### 1. 构建优化

**使用多阶段构建：**
- 已在 Dockerfile 中实现
- 减小最终镜像大小
- 提高构建速度

**使用构建缓存：**
```bash
# 使用 BuildKit
DOCKER_BUILDKIT=1 docker compose build
```

### 2. 运行时优化

**调整 Node.js 内存：**
```yaml
services:
  backend:
    environment:
      NODE_OPTIONS: "--max-old-space-size=512"
```

**启用 Nginx 缓存：**
```nginx
# 在 nginx.conf 中添加
proxy_cache_path /var/cache/nginx levels=1:2 keys_zone=api_cache:10m max_size=100m;

location /api {
    proxy_cache api_cache;
    proxy_cache_valid 200 5m;
    # ...
}
```

### 3. 数据库优化

**调整连接池：**
```env
DB_POOL_MIN=5
DB_POOL_MAX=20
```

**启用查询缓存：**
- 使用 Redis 缓存热点数据
- 实现查询结果缓存

### 4. 网络优化

**启用 HTTP/2：**
```nginx
listen 443 ssl http2;
```

**启用 Gzip 压缩：**
- 已在 Nginx 配置中启用
