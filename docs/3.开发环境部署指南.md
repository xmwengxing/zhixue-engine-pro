## 🛠 开发环境设置

### 必需工具

- **Node.js**: >= 18.0.0
- **pnpm**: >= 8.0.0 (推荐) 或 npm
- **Git**: >= 2.30
- **Docker**: >= 20.10 (用于本地数据库)
- **VS Code**: 推荐的 IDE

### 本地PostgreSQL服务端口占用注意！
- 已关闭PostgreSQL开机自动启动，临时开启使用命令
```
Start-Service -Name "postgresql-x64-18"
```
恢复开机自动启动
```
Set-Service -Name "postgresql-x64-18" -StartupType Automatic
Start-Service -Name "postgresql-x64-18"
```

### 初始化开发环境

```bash
# 1. 克隆项目
git clone <repository-url>
cd intelligent-training-platform

# 2. 安装 pnpm（如果未安装）
npm install -g pnpm

# 3. 启动数据库服务
docker-compose up -d postgres redis

# 4. 安装后端依赖
cd backend
pnpm install

# 5. 配置后端环境变量
cp .env.example .env
# 编辑 .env 文件

# 6. 运行数据库迁移
pnpm prisma migrate dev

# 7. 安装前端依赖
cd ../frontend
pnpm install

# 8. 配置前端环境变量
cp .env.example .env
# 编辑 .env 文件
```

### 启动开发服务器

```bash
# 终端 1: 启动后端
cd backend
pnpm dev

# 终端 2: 启动前端
cd frontend
pnpm dev
```

访问：
- 前端: http://localhost:5173
- 后端: http://localhost:3000
- Prisma Studio: `pnpm prisma studio` (http://localhost:5555)

## 🔄 开发工作流

### Git 工作流

我们使用 Git Flow 工作流：

```
main (生产分支)
  └── develop (开发分支)
        ├── feature/user-auth (功能分支)
        ├── feature/error-book (功能分支)
        └── bugfix/login-issue (修复分支)
```

### 分支命名规范

- `feature/功能名称`: 新功能开发
- `bugfix/问题描述`: Bug 修复
- `hotfix/紧急修复`: 生产环境紧急修复
- `refactor/重构内容`: 代码重构
- `docs/文档更新`: 文档更新

### 开发流程

1. **创建功能分支**
   ```bash
   git checkout develop
   git pull origin develop
   git checkout -b feature/new-feature
   ```

2. **开发功能**
   - 编写代码
   - 编写测试
   - 运行测试确保通过
   - 提交代码

3. **提交代码**
   ```bash
   git add .
   git commit -m "feat: 添加新功能"
   git push origin feature/new-feature
   ```

4. **创建 Pull Request**
   - 在 GitHub 上创建 PR
   - 填写 PR 描述
   - 等待 Code Review
   - 根据反馈修改代码

5. **合并代码**
   - PR 通过审核后合并到 develop
   - 删除功能分支

### 注释规范

```typescript
/**
 * 计算学员积分
 * @param difficulty - 题目难度 (1-5)
 * @param performance - 答题表现 (0-100)
 * @returns 获得的积分数
 */
function calculatePoints(difficulty: number, performance: number): number {
  // 基础积分 = 难度 * 10
  const basePoints = difficulty * 10;
  
  // 表现加成 = 基础积分 * 表现百分比
  const bonus = basePoints * (performance / 100);
  
  return Math.floor(basePoints + bonus);
}

// 单行注释用于简短说明
const MAX_POINTS = 1000; // 单次任务最大积分
```

## 💡 最佳实践

### 后端最佳实践

#### 1. 错误处理

```typescript
// ✅ 推荐：使用自定义错误类
class ValidationError extends Error {
  constructor(message: string, public details?: any) {
    super(message);
    this.name = 'ValidationError';
  }
}

// 在控制器中
try {
  const user = await userService.create(data);
  res.json({ user });
} catch (error) {
  if (error instanceof ValidationError) {
    res.status(422).json({ error: error.message, details: error.details });
  } else {
    next(error); // 传递给全局错误处理器
  }
}
```

#### 2. 数据验证

```typescript
// ✅ 推荐：使用 Zod 进行验证
import { z } from 'zod';

const createUserSchema = z.object({
  username: z.string().min(3).max(20),
  password: z.string().min(8),
  email: z.string().email().optional(),
});

// 在控制器中
const result = createUserSchema.safeParse(req.body);
if (!result.success) {
  return res.status(400).json({ errors: result.error.errors });
}
```

#### 3. 数据库查询优化

```typescript
// ❌ 避免：N+1 查询问题
const users = await prisma.user.findMany();
for (const user of users) {
  const profile = await prisma.profile.findUnique({
    where: { userId: user.id }
  });
}

// ✅ 推荐：使用 include 预加载
const users = await prisma.user.findMany({
  include: {
    profile: true,
  },

```

#### 4. 缓存策略

```typescript
// ✅ 推荐：使用 Redis 缓存
async function getUserProfile(userId: string) {
  // 先查缓存
  const cached = await redis.get(`user:${userId}`);
  if (cached) {
    return JSON.parse(cached);
  }

  // 缓存未命中，查数据库
  const profile = await prisma.profile.findUnique({
    where: { userId },
  });

  // 写入缓存（1 小时过期）
  await redis.setex(`user:${userId}`, 3600, JSON.stringify(profile));

  return profile;
}
```

#### 1. 输入验证

```typescript
// ✅ 始终验证用户输入
import { z } from 'zod';

const loginSchema = z.object({
```

#### 2. SQL 注入防护

```typescript

// ❌ 避免：原始 SQL 查询
```

#### 3. XSS 防护

```typescript
// ✅ React 自动转义

// ❌ 避免：使用 dangerouslySetInnerHTML
```


## 🤝 贡献指南

### 提交 Pull Request

1. **Fork 项目**
2. **创建功能分支**
   ```bash
   git checkout -b feature/amazing-feature
   ```

3. **提交更改**
   ```bash
   git commit -m "feat: 添加某个功能"
   ```

4. **推送到分支**
   ```bash
   git push origin feature/amazing-feature
   ```

5. **开启 Pull Request**

### Commit 消息规范

使用 Conventional Commits 规范：

```
<type>(<scope>): <subject>

<body>

<footer>
```

**Type**:
- `feat`: 新功能
- `fix`: Bug 修复
- `docs`: 文档更新
- `style`: 代码格式调整
- `refactor`: 重构
- `test`: 测试相关
- `chore`: 构建/工具链相关

**示例**:
```
feat(auth): 添加 JWT 刷新令牌功能

实现了 JWT 刷新令牌机制，允许用户在访问令牌过期后
无需重新登录即可获取新令牌。

Closes #123
```

- [ ] 添加了必要的测试
- [ ] 更新了相关文档
- [ ] 没有遗留的 console.log 或调试代码
- [ ] 提交消息符合规范
