## 🏗 部署架构

### 生产环境架构

```
                    ┌─────────────┐
                    │   用户浏览器  │
                    └──────┬──────┘
                           │
                    ┌──────▼──────┐
                    │    Nginx    │
                    │  (反向代理)  │
                    └──────┬──────┘
                           │
              ┌────────────┴────────────┐
              │                         │
       ┌──────▼──────┐          ┌──────▼──────┐
       │  前端静态文件  │          │  后端 API   │
       │   (React)    │          │  (Express)  │
       └──────────────┘          └──────┬──────┘
                                        │
                           ┌────────────┴────────────┐
                           │                         │
                    ┌──────▼──────┐          ┌──────▼──────┐
                    │ PostgreSQL  │          │    Redis    │
                    │   (数据库)   │          │   (缓存)    │
                    └─────────────┘          └─────────────┘
```

### 组件说明

- **Nginx**: 反向代理服务器，处理静态文件和 API 请求转发
- **前端**: React 单页应用，编译后的静态文件
- **后端**: Node.js Express API 服务器
- **PostgreSQL**: 主数据库，存储用户、任务、报告等数据
- **Redis**: 缓存服务器，存储会话和热点数据

## 💻 系统要求

### 最低配置

- **CPU**: 2 核
- **内存**: 4GB RAM
- **存储**: 20GB 可用空间
- **操作系统**: Ubuntu 20.04+ / CentOS 7+ / Debian 10+

### 推荐配置

- **CPU**: 4 核
- **内存**: 8GB RAM
- **存储**: 50GB SSD
- **操作系统**: Ubuntu 22.04 LTS

### 软件依赖

- Docker >= 20.10
- Docker Compose >= 2.0
- Node.js >= 18.0 (手动部署)
- PostgreSQL >= 15 (手动部署)
- Redis >= 7.0 (手动部署)
- Nginx >= 1.20 (手动部署)

## 🐳 Docker 部署（推荐）

Docker 部署是最简单和推荐的部署方式。

### 步骤 1: 安装 Docker

```bash
# Ubuntu/Debian
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh

# 安装 Docker Compose
sudo curl -L "https://github.com/docker/compose/releases/latest/download/docker-compose-$(uname -s)-$(uname -m)" -o /usr/local/bin/docker-compose
sudo chmod +x /usr/local/bin/docker-compose

# 验证安装
docker --version
docker-compose --version
```

### 步骤 2: 克隆项目

```bash
git clone <repository-url>
cd intelligent-training-platform
```

### 步骤 3: 配置环境变量

```bash
# 复制环境变量模板
cp .env.example .env

# 编辑环境变量
nano .env
```

**必须配置的环境变量**:

```env
# 数据库配置
POSTGRES_USER=training_user
POSTGRES_PASSWORD=<strong-password>
POSTGRES_DB=training_platform

# JWT 密钥（使用强随机字符串）
JWT_SECRET=<generate-random-string>

# AI 服务配置
OPENAI_API_KEY=sk-...
ANTHROPIC_API_KEY=sk-ant-...

# 域名配置（生产环境）
DOMAIN=yourdomain.com
```

生成随机密钥：
```bash
openssl rand -base64 32
```

### 步骤 4: 构建并启动服务

```bash
# 使用生产配置启动
docker-compose -f docker-compose.prod.yml up -d

# 查看服务状态
docker-compose -f docker-compose.prod.yml ps
```

### 步骤 5: 运行数据库迁移

```bash
# 等待数据库启动（约 10 秒）
sleep 10

# 运行迁移
docker-compose -f docker-compose.prod.yml exec backend pnpm prisma migrate deploy

# 可选：导入初始数据
docker-compose -f docker-compose.prod.yml exec backend pnpm prisma db seed
```

### 步骤 6: 验证部署

```bash
# 检查服务日志
docker-compose -f docker-compose.prod.yml logs -f

# 测试后端 API
curl http://localhost:3000/api/health

# 测试前端
curl http://localhost
```

### 步骤 7: 配置防火墙

```bash
# 允许 HTTP 和 HTTPS
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable
```

### Docker 常用命令

```bash
# 查看日志
docker-compose -f docker-compose.prod.yml logs -f [service-name]

# 重启服务
docker-compose -f docker-compose.prod.yml restart [service-name]

# 停止所有服务
docker-compose -f docker-compose.prod.yml down

# 更新服务
git pull
docker-compose -f docker-compose.prod.yml up -d --build

# 清理未使用的镜像
docker system prune -a
```

## 🔧 手动部署

如果不使用 Docker，可以手动部署各个组件。

### 步骤 1: 安装 Node.js

```bash
# 使用 nvm 安装 Node.js 18
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.0/install.sh | bash
source ~/.bashrc
nvm install 18
nvm use 18

# 安装 pnpm
npm install -g pnpm
```

### 步骤 2: 安装 PostgreSQL

```bash
# Ubuntu/Debian
sudo apt update
sudo apt install postgresql postgresql-contrib

# 启动服务
sudo systemctl start postgresql
sudo systemctl enable postgresql

# 创建数据库和用户
sudo -u postgres psql
```

在 PostgreSQL 命令行中：
```sql
CREATE USER training_user WITH PASSWORD 'your_password';
CREATE DATABASE training_platform OWNER training_user;
GRANT ALL PRIVILEGES ON DATABASE training_platform TO training_user;
\q
```

### 步骤 3: 安装 Redis

```bash
# Ubuntu/Debian
sudo apt install redis-server

# 启动服务
sudo systemctl start redis-server
sudo systemctl enable redis-server

# 验证
redis-cli ping
```

### 步骤 4: 部署后端

```bash
# 克隆项目
git clone <repository-url>
cd intelligent-training-platform/backend

# 安装依赖
pnpm install

# 配置环境变量
cp .env.example .env
nano .env

# 运行数据库迁移
pnpm prisma migrate deploy

# 构建项目
pnpm build

# 使用 PM2 启动服务
pnpm global add pm2
pm2 start dist/index.js --name training-backend
pm2 save
pm2 startup
```

### 步骤 5: 部署前端

```bash
cd ../frontend

# 安装依赖
pnpm install

# 配置环境变量
cp .env.example .env
nano .env

# 构建生产版本
pnpm build

# 将构建文件复制到 Nginx 目录
sudo cp -r dist/* /var/www/training-platform/
```

### 步骤 6: 配置 Nginx

```bash
# 安装 Nginx
sudo apt install nginx

# 创建配置文件
sudo nano /etc/nginx/sites-available/training-platform
```

配置内容：
```nginx
server {
    listen 80;
    server_name yourdomain.com;

    # 前端静态文件
    location / {
        root /var/www/training-platform;
        try_files $uri $uri/ /index.html;
    }

    # 后端 API 代理
    location /api {
        proxy_pass http://localhost:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

启用配置：
```bash
sudo ln -s /etc/nginx/sites-available/training-platform /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl restart nginx
```

### 数据库备份

#### 自动备份脚本

创建 `backup-db.sh`：

```bash
#!/bin/bash

# 配置
DB_NAME="training_platform"
DB_USER="training_user"
BACKUP_DIR="/var/backups/postgres"
DATE=$(date +%Y%m%d_%H%M%S)
BACKUP_FILE="$BACKUP_DIR/${DB_NAME}_${DATE}.sql.gz"

# 创建备份目录
mkdir -p $BACKUP_DIR

# 执行备份
pg_dump -U $DB_USER $DB_NAME | gzip > $BACKUP_FILE

# 删除 7 天前的备份
find $BACKUP_DIR -name "*.sql.gz" -mtime +7 -delete

echo "备份完成: $BACKUP_FILE"
```

设置定时任务：
```bash
chmod +x backup-db.sh

# 添加到 crontab（每天凌晨 2 点备份）
crontab -e
# 添加：0 2 * * * /path/to/backup-db.sh
```

#### 恢复数据库

```bash
# 解压并恢复
gunzip -c backup_file.sql.gz | psql -U training_user -d training_platform
```

## 🌐 Nginx 配置

### 完整生产配置

创建 `/etc/nginx/sites-available/training-platform`：

```nginx
# 上游后端服务器
upstream backend {
    server localhost:3000;
    keepalive 64;
}

# HTTP 重定向到 HTTPS
server {
    listen 80;
    server_name yourdomain.com www.yourdomain.com;
    return 301 https://$server_name$request_uri;
}

# HTTPS 主配置
server {
    listen 443 ssl http2;
    server_name yourdomain.com www.yourdomain.com;

    # SSL 证书
    ssl_certificate /etc/letsencrypt/live/yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/yourdomain.com/privkey.pem;
    
    # SSL 配置
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers on;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 10m;

    # 安全头
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-XSS-Protection "1; mode=block" always;
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;

    # Gzip 压缩
    gzip on;
    gzip_vary on;
    gzip_min_length 1024;
    gzip_types text/plain text/css text/xml text/javascript application/json application/javascript application/xml+rss;

    # 前端静态文件
    location / {
        root /var/www/training-platform;
        try_files $uri $uri/ /index.html;
        
        # 缓存静态资源
        location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf|eot)$ {
            expires 1y;
            add_header Cache-Control "public, immutable";
        }
    }

    # 后端 API 代理
    location /api {
        proxy_pass http://backend;
        proxy_http_version 1.1;
        
        # WebSocket 支持
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        
        # 代理头
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        
        # 超时设置
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
        
        # 缓存
        proxy_cache_bypass $http_upgrade;
    }

    # 健康检查
    location /health {
        proxy_pass http://backend/api/health;
        access_log off;
    }

    # 日志
    access_log /var/log/nginx/training-platform-access.log;
    error_log /var/log/nginx/training-platform-error.log;
}
```

### 启用配置

```bash
# 测试配置
sudo nginx -t

# 启用站点
sudo ln -s /etc/nginx/sites-available/training-platform /etc/nginx/sites-enabled/

# 重启 Nginx
sudo systemctl restart nginx
```

## 🔍 故障排查

### 常见问题

#### 1. 后端无法启动

**症状**: 后端服务启动失败或立即退出

**排查步骤**:
```bash
# 查看日志
docker-compose -f docker-compose.prod.yml logs backend
# 或
pm2 logs training-backend

# 检查端口占用
sudo lsof -i :3000

# 检查环境变量
docker-compose -f docker-compose.prod.yml exec backend env | grep DATABASE_URL

# 测试数据库连接
docker-compose -f docker-compose.prod.yml exec backend pnpm prisma db pull
```

**常见原因**:
- 数据库连接失败：检查 `DATABASE_URL`
- 端口被占用：更改端口或停止占用进程
- 环境变量缺失：检查 `.env` 文件

#### 2. 数据库连接失败

**症状**: `Error: P1001: Can't reach database server`

**排查步骤**:
```bash
# 检查 PostgreSQL 是否运行
docker-compose -f docker-compose.prod.yml ps postgres
# 或
sudo systemctl status postgresql

# 测试连接
psql -h localhost -U training_user -d training_platform

# 检查防火墙
sudo ufw status
```

**解决方案**:
```bash
# 重启数据库
docker-compose -f docker-compose.prod.yml restart postgres

# 检查数据库日志
docker-compose -f docker-compose.prod.yml logs postgres
```

#### 5. 内存不足

**症状**: 服务频繁重启或响应缓慢

**排查步骤**:
```bash
# 查看内存使用
free -h
docker stats

# 查看进程内存
ps aux --sort=-%mem | head -10
```

**解决方案**:
```bash
# 增加 swap 空间
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# 限制 Docker 容器内存
# 在 docker-compose.prod.yml 中添加：
services:
  backend:
    mem_limit: 1g
```

#### 6. 磁盘空间不足

**症状**: 写入操作失败

**排查步骤**:
```bash
# 查看磁盘使用
df -h

# 查找大文件
du -sh /* | sort -rh | head -10

# 查看 Docker 占用
docker system df
```

**解决方案**:
```bash
# 清理 Docker
docker system prune -a

# 清理日志
sudo journalctl --vacuum-time=7d

# 清理旧备份
find /backups -mtime +30 -delete
```
