# 📐 电子答题专区 — 完整设计方案

---

## 一、为什么必须做电子答题专区？

| 问题 | 手写拍照上传 | 电子答题专区 |
|------|-------------|-------------|
| **识别准确率** | 小学生字迹潦草，OCR准确率仅60-80% | 结构化输入，准确率接近100% |
| **数学公式** | 手写分数、根号、积分符号极难识别 | 公式编辑器所见即所得 |
| **几何图形** | 拍照后AI难以理解图形语义 | 交互式绘图，数据可解析 |
| **批改效率** | 需AI"猜"答案，幻觉风险高 | 答案结构化，规则引擎即可批改 |
| **错题归档** | 图片无法检索、无法变式 | 结构化数据，精准匹配同类题 |

> 核心思路：**不是取消手写，而是"能电子化的电子化，必须手写的保留手写"**，两条通道并行。

### 2.2 各题型详细设计

#### ✅ 第一梯队：容易实现

| 题型 | 交互方式 | 技术实现 | 批改方式 |
|------|----------|----------|----------|
| **选择题** | 点击选项（A/B/C/D），支持单选/多选 | 标准 Radio/Checkbox 组件 | 规则引擎精确匹配 |
| **判断题** | 点击 ✓ / ✗ 按钮 | 两个大按钮，适合儿童操作 | 规则引擎 |
| **排序题** | 拖拽排序 | 拖拽库（dnd-kit / flutter_reorderable） | 序列比对 |
| **连线题** | 拖线连接左右两列 | SVG/Canvas 画线 + 碰撞检测 | 匹配关系验证 |

#### ⚡ 第二梯队：中等难度（需公式支持）

| 题型 | 交互方式 | 技术实现 | 批改方式 |
|------|----------|----------|----------|
| **填空题（含公式）** | 文本输入 + 公式编辑器混排 | **MathLive** `<math-field>` 组件 [[91]][[93]] | 规则引擎 + LaTeX 语义比对 |
| **计算题** | 公式编辑器输入完整解题过程 | MathLive / MathQuill [[29]][[48]] | 分步验证（每步结果校验） |
| **简答题** | 富文本编辑器 + 公式插入 | TipTap/Quill + MathLive 插件 [[26]] | LLM 语义评判 |

#### 🔥 第三梯队：核心难点（公式+图形）

| 题型 | 交互方式 | 技术实现 | 批改方式 |
|------|----------|----------|----------|
| **几何作图题** | 交互式画布：画点、线、圆、角 | **GeoGebra API** 或 **Desmos Geometry API** [[78]][[143]] | 几何关系验证（平行、垂直、等长等） |
| **函数绘图题** | 输入函数表达式 → 自动绘图 | **Desmos Graphing API** [[32]][[79]] | 函数表达式比对 + 图形特征验证 |
| **物理公式题** | 公式编辑器 + 单位选择 | MathLive + 自定义物理符号面板 | 规则引擎 + 单位校验 |
| **证明题** | 分步输入：条件→推理→结论 | 结构化表单 + 公式编辑器 | LLM 逻辑链验证 |

#### 📝 第四梯队：手写兜底

| 题型 | 交互方式 | 技术实现 | 批改方式 |
|------|----------|----------|----------|
| **复杂手写** | 平板+触控笔手写 | **MyScript iink SDK** [[101]][[103]] 或 **MathType Hand** [[152]][[154]] | 手写识别→LaTeX→规则/LLM批改 |
| **自由作答** | 手写板（Canvas） | 自研 Canvas 手写组件 | 图片→OCR→LLM批改（兜底） |

## 三、核心技术方案详解

### 3.1 数学/物理公式输入 — 三套方案对比

| 方案 | 技术 | 优势 | 劣势 | 适用场景 |
|------|------|------|------|----------|
| **方案A：MathLive** | Web Component `<math-field>` [[93]][[97]] | 开箱即用、支持React [[92]]、虚拟键盘、LaTeX输出、移动端友好 [[46]] | 自定义符号面板需额外开发 | **首选方案**，覆盖K12所有公式 |
| **方案B：MathQuill** | JavaScript 库 [[29]][[30]] | Khan Academy 验证 [[48]]、轻量、WYSIWYG | 移动端体验略弱、维护频率低 | Web端备选 |
| **方案C：MathType + 手写** | SDK + 手写识别 [[152]][[154]] | 支持手写→公式转换 [[153]]、教育行业标准 | 商业授权费用高、集成复杂 | 平板手写场景 |

**推荐：MathLive 为主 + MathType Hand 为辅（平板手写场景）**

#### MathLive 集成示例（React）

```jsx
// 安装: npm install mathlive
import 'mathlive';

function FormulaInput({ value, onChange }) {
  return (
    <math-field
      value={value}
      onInput={(e) => onChange(e.target.value)}
      virtual-keyboard-mode="onfocus"    // 移动端自动弹出虚拟键盘
      math-virtual-keyboard-policy="manual"
      style={{ fontSize: '1.2em', padding: '8px' }}
    >
      {value}
    </math-field>
  );
}

// 输出为 LaTeX 字符串，如: \frac{x^2 + 1}{\sqrt{3}}
// 后端可用 KaTeX 渲染 [[28]]，或 sympy 做语义比对
```

### 3.2 几何图形绘制 — 三套方案对比

| 方案 | 技术 | 优势 | 劣势 | 适用场景 |
|------|------|------|------|----------|
| **方案A：GeoGebra 嵌入** | iframe / JavaScript API [[10]][[143]] | 功能最强大、教育行业标准、免费 [[58]] | 嵌入定制性有限、UI风格不统一 | 复杂几何作图、函数绘图 |
| **方案B：Desmos API** | JavaScript SDK 嵌入 [[32]][[78]][[79]] | API设计优雅、60秒即可嵌入 [[79]]、几何+图形+3D [[34]] | 商业使用需授权、中文支持一般 | 函数绘图、坐标系题目 |
| **方案C：自研 Canvas 画板** | tldraw SDK [[134]][[135]] 或自研 | 完全可控、UI统一、可深度定制 | 开发量大、几何约束需自研 | 简单图形、自由绘图 |

**推荐：分层策略**

```
简单图形（画线段、标角度）→ 自研 Canvas（基于 tldraw SDK [[134]]）
标准几何作图（尺规作图）→ GeoGebra 嵌入 [[143]]
函数图像（画函数曲线）  → Desmos Graphing API [[79]]
自由绘图（辅助线草稿）  → tldraw 画布 [[120]][[135]]
```

#### GeoGebra 嵌入示例

```html

### 3.3 手写输入（平板场景）— 保留手写体验

对于**必须手写**的场景（如复杂证明题的辅助线、自由演算），提供手写板：

| 方案 | 技术 | 能力 | 平台 |
|------|------|------|------|
| **MyScript iink SDK 3.0** [[101]][[102]] | 商业SDK | 手写→文字/公式/图形实时转换，支持70+语言 [[63]]，数学公式识别 [[64]][[126]] | Web/iOS/Android |
| **MathType Hand** [[152]][[154]] | 商业SDK | 手写公式→LaTeX转换 [[153]]，教育行业标准 | Web |
| **自研 Canvas + OCR** | 开源 | 自由手写→拍照→OCR识别（兜底） | 全平台 |

**MyScript 的核心优势**：学生用触控笔在平板上**像纸上一样书写**，SDK 实时将手写内容转换为结构化数学表达式 [[64]][[126]]，既保留了手写的自然体验，又获得了电子化的精准数据。

```
学生手写: ∫₀¹ x² dx  →  MyScript 实时识别  →  LaTeX: \int_0^1 x^2 \, dx
                                                    ↓
                                              结构化数据 → 规则引擎批改
```

### 3.4 答题数据模型设计

```typescript
// 统一答题数据结构
interface AnswerSubmission {
  questionId: string;
  questionType: QuestionType;
  studentId: string;
  
  // 根据题型不同，答案格式不同
  answer: 
    | MultipleChoiceAnswer    // { selected: ['A', 'C'] }
    | TrueFalseAnswer         // { value: true }
    | FillBlankAnswer         // { blanks: [{ text: '...', latex: '\\frac{1}{2}' }] }
    | FormulaAnswer           // { latex: '\\frac{x^2+1}{\\sqrt{3}}', steps: [...] }
    | GeometryAnswer          // { ggbState: '...', constructions: [...] }
    | GraphAnswer             // { expressions: ['y=2x^2+1'], desmosState: '...' }
    | HandwritingAnswer       // { imageUrl: '...', recognizedLatex: '...', confidence: 0.95 }
    | EssayAnswer;            // { richText: '...', formulas: [...] }
  
  // 元数据
  timeSpent: number;          // 答题用时（秒）
  inputMethod: 'click' | 'keyboard' | 'formula_editor' | 'handwriting' | 'drawing';
  submittedAt: string;
}

enum QuestionType {
  MULTIPLE_CHOICE = 'multiple_choice',
  TRUE_FALSE = 'true_false',
  FILL_BLANK = 'fill_blank',
  FORMULA_CALC = 'formula_calc',
  GEOMETRY = 'geometry',
  GRAPHING = 'graphing',
  PROOF = 'proof',
  ESSAY = 'essay',
  HANDWRITING = 'handwriting',  // 兜底：自由手写
}
```

### 4.2 输入方式智能切换

```
题目类型自动判断 → 推荐输入方式：

选择题/判断题     → 点击选择（最简单）
纯数字填空       → 数字键盘

```

> 关键设计原则：**学生永远有"拍照上传"兜底选项**，不强制电子化。

## 五、批改引擎适配

电子答题后，批改逻辑大幅简化：

```
┌──────────────────────────────────────────────────────────┐
│                    批改引擎 (Grading Engine)               │
│                                                          │
│  输入: AnswerSubmission (结构化数据)                       │
│                                                          │
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐   │
│  │ 规则引擎     │    │ 语义比对     │    │ LLM 评判    │   │
│  │ (精确匹配)   │    │ (等价判断)   │    │ (开放题)    │   │
│  ├─────────────┤    ├─────────────┤    ├─────────────┤   │
│  │ 选择题 ✓    │    │ 公式等价 ✓  │    │ 简答题 ✓    │   │
│  │ 判断题 ✓    │    │ 1/2 = 0.5  │    │ 证明题 ✓    │   │
│  │ 排序题 ✓    │    │ x²-1=(x+1) │    │ 作文 ✓      │   │
│  │ 连线题 ✓    │    │  ×(x-1)    │    │             │   │
│  │ 几何关系 ✓  │    │ 几何等价 ✓  │    │             │   │
│  └─────────────┘    └─────────────┘    └─────────────┘   │
│                                                          │
│  输出: { score, isCorrect, errorAnalysis, feedback }      │
└──────────────────────────────────────────────────────────┘
```

**关键优势**：
- 选择题/判断题：**0成本、0延迟、100%准确**
- 公式计算：LaTeX 语义比对（`sympy` 库判断等价性），**不需要 LLM**
- 几何作图：验证几何约束（平行、垂直、等长），**规则引擎即可**
- 只有简答题/证明题才需要调用 LLM，**大幅降低 AI API 成本**

## 新增模块：电子答题专区 (Answer Zone)

### 模块概述
设计一个结构化的电子答题专区，替代/补充传统的"拍照上传"模式。
核心目标：让学生直接在设备上完成答题，获得结构化答案数据，
彻底解决手写OCR识别不准确的问题。

设计原则：
1. 能电子化的电子化（选择、判断、公式、几何）
2. 必须手写的提供手写板（MyScript 实时识别）
3. 永远保留"拍照上传"兜底选项
4. 输入方式根据题型自动推荐，学生可手动切换

### 技术集成要求

#### 1. 公式编辑器 — MathLive
- 安装: npm install mathlive
- 使用 <math-field> Web Component [[93]]
- React 集成: 参考官方指南 [[92]]
- 移动端: 启用虚拟键盘 (virtual-keyboard-mode="onfocus") [[46]]
- 自定义虚拟键盘布局:
  - 基础面板: + - × ÷ = ≠ < > ( ) [ ]
  - 分数/根号面板: a/b √ ∛ x² xⁿ
  - 几何面板: ∠ △ ∥ ⊥ ° π
  - 函数面板: sin cos tan log ln lim Σ ∫
  - 希腊字母: α β γ θ λ μ
- 输出格式: LaTeX 字符串
- 渲染: 使用 KaTeX [[28]] 在题目展示区渲染公式

#### 2. 几何画布 — GeoGebra 嵌入
- 使用 GeoGebra JavaScript API [[10]][[143]]
- 嵌入模式: iframe 或 JS API
- 几何题目预设:
  - 通过 appletOnLoad 预设已知条件（点、线、圆）
  - 学生使用工具栏完成作图（画线、画圆、标角度）
  - 提交时获取 GeoGebra 状态 (getBase64 / getXML)
- 批改: 提取几何对象，验证约束关系
  - 例: 验证 "线段AD ⊥ BC" → 检查斜率乘积 = -1
  - 例: 验证 "圆O过A、B、C三点" → 检查三点到圆心距离相等

#### 3. 函数绘图 — Desmos API
- 使用 Desmos Graphing Calculator API [[32]][[79]]
- 申请 API Key: https://www.desmos.com/api [[78]]
- 嵌入: <script src="https://www.desmos.com/api/v1.12/calculator.js?apiKey=KEY">
- 预设: 显示题目给定的函数图像
- 学生: 在表达式栏输入自己的函数
- 提交: 获取所有表达式 (calculator.getExpressions())
- 批改: 
  - 表达式语义比对 (sympy 判断等价)
  - 图形特征验证 (顶点、对称轴、零点)

#### 4. 自由画布 — tldraw SDK
- 安装: npm install tldraw [[134]][[135]]
- 用途: 辅助线草稿、自由绘图、标注
- 教育模板: 参考 tldraw education canvas [[120]]
- 自定义形状: 角度标注、平行标记、全等标记
- 导出: SVG / PNG

#### 5. 手写识别 — MyScript iink SDK
- 使用 MyScript iink SDK 3.0 [[101]][[103]]
- 数学识别: 手写公式 → LaTeX [[64]][[102]]
- 平台: Web (JavaScript) / iOS / Android
- 集成方式:
  - Web: iink JS SDK
  - iOS: iink iOS SDK (Swift)
  - Android: iink Android SDK (Kotlin)
- 功能:
  - 实时手写 → 文字/公式转换
  - 涂改擦除 (scratch to erase) [[64]]
  - 支持混合内容 (文字+公式+图形)
- 备选: MathType Hand SDK [[152]][[154]]

#### 6. 富文本编辑 — TipTap + 公式
- 安装: npm install @tiptap/react @tiptap/starter-kit
- 公式插件: 集成 MathLive 作为 TipTap 扩展
- 参考: mathquill4quill 的集成思路 [[26]]
- 用途: 简答题、证明题的图文混排

#### 核心交互流程
```
1. 学生进入答题专区
2. 系统根据题目类型自动选择输入组件
3. 学生答题（可切换输入方式）
4. 点击"提交答案"
5. 前端打包 AnswerSubmission 对象
6. POST /api/corrections/submit-electronic
7. 后端批改引擎处理:
   - 选择题/判断题 → 规则引擎 (0延迟)
   - 公式计算 → LaTeX解析 + sympy等价判断
   - 几何作图 → 提取几何对象 + 约束验证
   - 函数绘图 → 表达式比对 + 特征点验证
   - 简答题/证明题 → LLM语义评判
   - 手写内容 → MyScript识别 → 再走上述流程
8. 返回批改结果 → 前端展示
9. 错题 → 自动进入错题银行
```

| GeoGebra | **教育用途免费** [[58]] | 中风险：嵌入定制性有限 |
| Desmos API | **需申请Key，教育免费** [[78]] | 中风险：商业使用条款需确认 |
| tldraw SDK | **开源（有商业许可）** [[134]] | 低风险 |
| MyScript iink | **商业授权，按设备数收费** [[103]] | 高风险：成本较高，需评估ROI |
| MathType Hand | **商业授权** [[152]] | 中风险 |

> 💡 **建议**：MVP 阶段先集成 MathLive + KaTeX + GeoGebra（全部免费），手写识别用 Canvas + OCR 兜底。等验证产品价值后，再引入 MyScript 提升手写体验。

---

总结一下核心建议：

1. **必须做电子答题专区**，这是解决OCR不准确问题的根本方案
2. **公式输入用 MathLive**（免费、成熟、移动端友好）
3. **几何用 GeoGebra 嵌入 + 函数用 Desmos API**（教育行业标准）
4. **手写不是取消，而是降级为兜底方案**（MyScript 或拍照上传）
5. **批改成本大幅降低**：结构化数据让80%的题目可以用规则引擎批改，只有开放题才需要 LLM
