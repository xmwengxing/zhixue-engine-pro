# 题库管理 + 题库组卷任务 + 电子答题专区 实施计划

> 对齐文档：`docs/电子答题专区开发方案.md`（已评估，整体可行，需按本栈"翻译"）
> 决策基线（来自需求确认）：
> - **识别方案**：OCR + 大模型两段式（文本层提取 / 扫描件走 OCR → LLM 归一化）
> - **导入格式**：Word(.docx)、PDF、图片/拍照、纯文本/Markdown（首期不含 Excel/CSV）
> - **答题区范围**：完整版（MathLive + KaTeX + GeoGebra + Desmos + MyScript + 拍照兜底）
> - **科目体系**：复用 `SubjectInstruction.subject`（数学/语文/英语…），不新建科目模型

---

## 0. 总体架构

```
管理员端                      家长端/AI                     学员端
┌──────────────┐         ┌──────────────────┐        ┌──────────────────┐
│ 题库管理      │         │ 发布任务          │        │ 电子答题专区      │
│ - 科目分类    │         │ + 新模式下拉      │        │ AnswerZone 引擎   │
│ - 导入试卷    │ ─ref→   │  套卷发布         │ ─task→ │ 按题型切换输入     │
│   (docx/pdf/  │         │  随机抽题组卷     │        │ 公式/几何/函数/    │
│    图片/文本) │         │ AI smartAssign    │        │ 手写/拍照         │
│ - OCR→LLM    │         │  亦支持该模式      │        │      │           │
│   归一化审核  │         └──────────────────┘        │      ▼           │
│ - 标准化入库  │                                      │ 结构化提交        │
└──────────────┘                                      │      ▼           │
                                                       │ 批改引擎          │
                                                       │ 规则/等价/LLM     │
                                                       └──────────────────┘
```

核心数据关系：`QuestionPaper(试卷)` 1—N `QuestionPaperItem` N—1 `Question(标准题元)`；
`Task(mode=EXAM_PAPER)` 引用 paper 或随机条件 → 生成 `TrainingSession.questions`；
学员 `Answer` 新增 `answerData`(结构化) + `inputMethod`。

## 1. 目标 1：管理员端题库（科目分类 + 导入识别）

### 1.1 数据模型（Prisma 扩展，Postgres）

```prisma
// 扩充题型枚举（保留 CHOICE/FILL/ESSAY，新增）
enum QuestionType {
  CHOICE          // 单选（兼容现有 AI 生成题）
  MULTIPLE_CHOICE // 多选
  JUDGE           // 判断
  FILL            // 填空（兼容现有）
  FORMULA         // 含公式的计算/填空
  GEOMETRY        // 几何作图
  GRAPHING        // 函数绘图
  PROOF           // 证明/说理
  ESSAY           // 简答/作文（兼容现有）
  SORTING         // 排序
  MATCHING        // 连线
}

// 试卷（一套卷）
model QuestionPaper {
  id         String      @id @default(uuid())
  subject    String                         // 复用 SubjectInstruction.subject
  title      String
  grade      String?
  sourceFile String?     @map("source_file") // 上传原件路径
  status     PaperStatus @default(DRAFT)    // DRAFT→NORMALIZED→PUBLISHED
  createdBy  String      @map("created_by")
  createdAt  DateTime    @default(now()) @map("created_at")
  items      QuestionPaperItem[]
  @@map("question_papers")
}

// 卷内题序与分值
model QuestionPaperItem {
  id         String   @id @default(uuid())
  paper      QuestionPaper @relation(fields: [paperId], references: [id])
  paperId    String   @map("paper_id")
  question   Question @relation(fields: [questionId], references: [id])
  questionId String   @map("question_id")
  order      Int      @default(0)
  score      Int      @default(0)
  @@unique([paperId, questionId])
  @@map("question_paper_items")
}

// 扩展现有 Question（不替换，向后兼容）
model Question {
  // ... 现有字段 ...
  answerType   String?  @map("answer_type")   // 归一化题型键，驱动输入/批改
  answerConfig Json?    @map("answer_config")  // 选项/正确答案/expectedLatex/几何预设
  paperItems   QuestionPaperItem[]
}
```

### 1.2 导入与识别流程（OCR + 大模型两段式）

```
上传文件 ──► 格式解析层 ──────────────► 文本/版面层 ──► LLM 归一化 ──► 校验 ──► 人工审核 ──► 入库
  docx   ──► mammoth 提取 HTML/文本                                  (zod schema)
  pdf(数字)─► pdf-parse / pdftotext 文本                                │
  pdf(扫描)/图片 ─► OCR 层(见1.3) 文本+坐标 ───────────────────────────┘
  纯文本/Markdown ──► 直接送 LLM
```

**标准范式（题元 JSON Schema，强制 LLM 输出遵守）**：
```ts
interface NormalizedQuestion {
  subject: string;          // 必须命中已有 SubjectInstruction.subject
  grade?: string;
  type: QuestionType;       // 上述枚举
  stem: string;             // 题干（公式用 LaTeX 占位）
  options?: string[];       // 选择/判断
  answer: string;           // 标准答案（选择用 "A,C"；公式用 LaTeX）
  analysis?: string;        // 解析
  difficulty: 1|2|3|4|5;
  knowledgePoints: string[];
  score?: number;
}
```
- LLM 调用采用 **JSON Mode + zod 校验 + few-shot 示例**，输出不合规则重试/标记 `needsReview`。
- 管理端提供**逐题审核界面**：展示原文片段 + 解析结果，可改题型/答案/知识点后再 `PUBLISHED`。

### 1.3 OCR 方案（两段式的第一段）

- **数字 docx / 数字 PDF**：无需 OCR，直接文本层（mammoth / pdf-parse）。
- **扫描 PDF / 图片（目标格式包含图片）**：OCR 层可插拔：
  - 开发态默认：调用**已配置的视觉大模型**产出「文本+版面位置」作为 OCR（复用现有 AI 服务，零额外密钥）。
  - 生产态可选：腾讯云/百度智能云 OCR（需密钥，连接器未连通时留 `ocrProvider` 接口）。
- 设计 `ocrProvider` 抽象，便于后续替换为商业 OCR，不阻塞主流程。

### 1.4 管理端 UI
- 侧边栏新增「题库」(`/admin/question-bank`)：科目 Tab + 试卷列表 + 题目列表。
- 「导入试卷」：拖拽上传（docx/pdf/图片/文本）→ 进度 → 归一化结果审核页。
- 题目卡片展示题型/难度/知识点/答案，可编辑、可加入/移出某套卷。

### 1.5 新增 API
```
POST /admin/question-bank/import        # 上传+触发解析（返回 jobId）
GET  /admin/question-bank/import/:jobId # 轮询归一化结果
PUT  /admin/question-bank/questions/:id # 审核/编辑
POST /admin/question-bank/papers        # 建卷
POST /admin/question-bank/papers/:id/items # 加题
```

## 2. 目标 2：题库组卷任务模式（家长 / AI 均可发起）

### 2.1 数据模型
```prisma
enum TaskMode { PROFILE CUSTOM EXAM_PAPER }  // 新增 EXAM_PAPER

// Task.config 在 EXAM_PAPER 模式下含义：
// {
//   source: 'paper' | 'random',
//   paperId?: string,            // 套卷发布
//   subject?: string,
//   knowledgePoints?: string[],  // 随机抽题范围
//   count?: number,             // 随机抽题数量
//   difficultyDistribution?: { easy:number; medium:number; hard:number },
//   timeLimit?: number
// }
```

### 2.2 组卷服务 `examPaperService`
- `buildFromPaper(paperId)`：取卷内题 → 生成 `TrainingSession.questions`（保持卷序/分值）。
- `buildRandom({subject, knowledgePoints, count, difficulty})`：从 `Question` 按条件抽样，优先命中薄弱知识点（结合 IRT/错题数据）。

### 2.3 家长端 + AI 派单
- 家长建任务页 (`/parent/tasks/create`) 新增「从题库组卷」模式：选科目 → 选「套卷发布」(下拉卷) 或「随机抽题」(选知识点+数量+难度)。
- `parentTaskService.smartAssign` 增加 `mode:'exam_paper'` 分支：默认按近 3 天薄弱知识点随机抽题组卷（复用目标1的聚合数据）。
- `studentTrainingService.start` 在 `EXAM_PAPER` 模式下改为从 `Task.config` 取题，而非 AI 实时生成。

## 3. 目标 3：电子答题专区（完整版）

### 3.1 数据模型
```prisma
// Answer 扩展（保留 studentAnswer 字符串，向后兼容）
model Answer {
  // ...现有...
  answerData  Json?   @map("answer_data")   // 结构化答案（见 3.4）

```

### 3.2 题型 → 输入组件映射
| 梯队 | 题型 | 输入组件 | 批改 |
|---|---|---|---|
| 一 | 选择/多选 | Radio/Checkbox | 规则精确匹配 |
| 一 | 判断 | ✓/✗ 按钮 | 规则 |
| 一 | 排序/连线 | dnd-kit 拖拽/SVG 连线 | 序列/匹配比对 |
| 二 | 填空(含公式) | 文本+MathLive | 规则+LaTeX 等价 |
| 二 | 计算/公式 | MathLive 编辑器（分步） | 分步等价校验 |
| 二 | 简答/证明 | TipTap 富文本+MathLive | LLM 语义 |
| 三 | 几何作图 | **GeoGebra** 嵌入 | 提取对象+约束验证 |
| 三 | 函数绘图 | **Desmos** 嵌入 | 表达式等价+特征点 |
| 四 | 复杂手写 | **MyScript** 手写板 | 识别→LaTeX→规则/LLM |
| 四 | 兜底 | 拍照上传(Canvas) | OCR→LLM |

### 3.3 组件清单（`frontend/src/components/answer/`）
```
AnswerZone/
├── QuestionRenderer/   (Text/Formula(KaTeX)/Image/Geometry)
├── AnswerInput/
│   ├── Choice.tsx  Judge.tsx  FillBlank.tsx  FormulaCalc.tsx
│   ├── GeometryDraw.tsx   (GeoGebra)
│   ├── FunctionGraph.tsx  (Desmos)
│   ├── ProofWriter.tsx  EssayEditor.tsx (TipTap+MathLive)
│   ├── HandwritingPad.tsx (MyScript)
│   └── PhotoUpload.tsx
├── ToolBar/  (公式键盘/几何工具/输入切换/拍照)
└── AnswerZoneContainer.tsx
```
- 题目渲染区用 **KaTeX** 渲染公式；输入区按 `Question.answerType` 自动选组件，学生可手动切换。

### 3.4 批改引擎 `gradingEngine`
- 选择/判断/排序/连线/几何约束：**规则引擎，零 LLM 成本**。
- 公式等价：`POST /api/formula/verify` —— **新增轻量 Python(sympy) 微服务**（本栈已有 Python 运行时），判断 LaTeX 代数/数值等价；Node 侧用 `nerdamer` 作兜底。
- 几何：解析 GeoGebra `getXML()` 提取对象，验证平行/垂直/等长等约束。
- 简答/证明：仅此类走 LLM 语义评判（复用现有 AI 服务）。

### 3.5 外部 SDK 集成与前置条件（完整版必需）
| 组件 | 方案 | 前置条件 |
|---|---|---|
| 公式编辑 | **MathLive**（开源免费） | 无 |
| 公式渲染 | **KaTeX**（开源免费） | 无 |
| 几何 | **GeoGebra JS API**（教育免费） | 无 |
| 函数 | **Desmos Graphing API** | **需申请 API Key**（教育免费，商业条款待确认） |
| 手写 | **MyScript iink SDK** | **商业授权**（按设备/云调用计费） |
| 富文本 | TipTap + MathLive | 无 |

> ⚠️ **前置风险**：Desmos Key、MyScript 授权需你方提供。计划按"先免费后商业"切片：
> GeoGebra/Desmos/MyScript 各自独立集成，**任一缺失时退化为 Canvas 自由作图 / 拍照上传兜底**，不阻塞其它题型上线。

## 4. 分阶段执行计划

| 阶段 | 范围 | 关键产物 | 依赖 |
|---|---|---|---|
| **A. 题库底座** | 数据模型迁移 + 管理端题库页 + 题目 CRUD | `QuestionPaper/Item` 模型、科目 Tab、审核页 | 无 |
| **B. 导入识别** | docx/PDF/文本解析 + LLM 归一化 + 审核入库 | import 流水线、zod 范式、OCR 抽象 | A |
| **C. 组卷任务** | `EXAM_PAPER` 模式 + 家长/AI 派单 + 组卷服务 | `examPaperService`、建任务 UI | A |
| **D. 答题基础** | 选择/判断/填空/简答 + MathLive/KaTeX + 规则批改 | AnswerZone 基础组件、answerData 落库 | A |

| **F. 手写/兜底** | MyScript 手写板 + 拍照上传 | 手写组件（需授权） | D |

> 说明：B 的图片 OCR、E 的 Desmos、F 的 MyScript 在密钥/授权到位前以"免费组件 + 拍照兜底"实现，到位后替换。

## 5. 需统一的历史不一致（顺带治理）
- 后端 `Question.type` 枚举为 `CHOICE/FILL/ESSAY`，而前端 `TrainingCabin` 用 `single_choice/multiple_choice/fill_blank/short_answer`。计划统一到新的 `QuestionType` 枚举，前端做映射层。
- `Answer.studentAnswer` 保持字符串（兼容旧训练），新答题走 `answerData`。

## 6. 风险与前置条件清单
1. **Desmos API Key**、**MyScript 商业授权**需提供（否则相关题型降级为拍照/Canvas 兜底）。
2. **公式符号等价**：建议新增 Python(sympy) 微服务；若不愿新增服务，则用 Node `nerdamer` 近似（代数等价覆盖略弱）。
3. **OCR 视觉能力**：开发态默认用已配置视觉大模型；生产 OCR（腾讯/百度）需密钥。
4. **现有 AI 服务连通性**：本环境 `subjectInstruction` 已 seed，但 AI Provider 未配置，归一化/批改的 LLM 环节需在具备 AI 密钥时联调（同此前 smartAssign 情况）。

## 7. 验收标准（分阶段）
- A：管理端可建科目分类、建卷、查看/编辑题目。
- B：上传 docx/PDF/文本→ 归一化为标准题元→ 审核→ 入库；图片走 OCR→归一化。
- C：家长与 AI 均可发起「套卷发布 / 随机抽题」任务，学员端能进入作答。
- D：选择/判断/填空/简答可在设备上结构化作答，规则引擎即时批改，错题入错题本。
- E：公式/几何/函数题型可电子化输入并验证。
- F：手写板可用（授权到位后），拍照上传兜底全题型可用。
